# v0.19.0 Withdrawn Release Audit

Date: 2026-08-10
Disposition: **WITHDRAWN TO DRAFT — NOT A RELEASE CANDIDATE**

## Trigger

Repository inspection found a public `v0.19.0` GitHub Release while the
professional release scorecard still recorded a `NO-GO` decision. The public
record was audited instead of treating its published state as proof of release
quality.

## Findings

1. The published Release targeted `251f34bf5a9030dcb89c61223654326104d69222`.
   Final remediation main is
   `e00181fc5b6d105249415d8e69bfb315c52b5b87`; the published target is its
   ancestor and excludes PR #28 and PR #30.
2. The Release body claimed signed-installer validation and instructed users
   to download signed Windows packages. It was also malformed: PowerShell
   `FileInfo`/provider metadata had been serialized into the body.
3. The published NSIS asset metadata reported:
   - name: `wancode_0.19.0_x64-setup.exe`
   - size: `25,496,316` bytes
   - GitHub digest:
     `sha256:cc413dbe9ae2b007974cb61286239bbe09dee45dd473679447b55a7a6738592a`
4. A range-complete PE header was downloaded from that exact asset. The PE
   Optional Header Security Directory contained:
   - certificate table file offset: `0`
   - certificate table size: `0`

   A zero Security Directory proves that the executable has no embedded
   Authenticode signature. The adjacent `.sig` asset is the Tauri updater
   signature; it is not Windows Authenticode and does not establish publisher
   trust.
5. The Release also contained an MSI, but an MSI signature was not promoted to
   PASS because the complete asset could not be downloaded over the unstable
   connection and no independent Authenticode evidence existed.

## Containment

The public Release was converted back to Draft. GitHub now reports v0.18.9 as
Latest. The tag and assets remain attached to the Draft for auditability; they
must not be reused for the final release.

## Release rule

The final v0.19.0 Release must be created from the exact approved main SHA.
Both NSIS and MSI assets must report `Valid` through
`Get-AuthenticodeSignature`, expose the expected publisher certificate, match
the durable SHA-256 manifest, and pass clean-host installation evidence before
the Release can leave Draft state.
