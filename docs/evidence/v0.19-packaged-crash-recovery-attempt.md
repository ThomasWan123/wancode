# WanCode v0.19 packaged crash-recovery attempt

Date: 2026-08-09  
Product candidate: `0b86c77bce151fd447f23c47e3b28d3986d54577`  
Result: **BLOCKED BY THE LOCAL GUI/AUTOTEST LAUNCH ENVIRONMENT**

## Objective

Create a real session, force-terminate WanCode after the first successful turn,
then launch the installed release candidate and verify that the recovery banner
restores the exact session before the dirty marker is acknowledged.

## Isolation

The attempt used the disposable root `D:\WANCode\qa-crash-e2e` and isolated all
application-controlled state:

- `GROK_HOME`;
- `APPDATA` and `LOCALAPPDATA`;
- `TEMP` and `TMP`;
- the WebView2 user-data directory;
- the AUTOTEST workspace and surface-binding store.

The real model configuration was copied into the isolated engine home. Its
contents and credentials were not printed. No real user session or sidecar was
modified.

## Observed result

The current-head debug executable was launched from a clean Windows PowerShell
process with a canonicalized `Path`. WebView2 initialized a complete isolated
profile, proving that the GUI process started and reached browser-runtime
initialization. However, during the 181.4-second bounded run:

- no `wancode-autotest.log` file was created;
- no `SMOKE S1-start PASS` event was emitted;
- redirected stderr remained empty;
- no session directory, dirty recovery marker, or binding was created;
- the exact launched process was force-stopped at the bound, and no WanCode
  process remained.

PowerShell 7, which is the documented smoke launcher, was not installed or on
`PATH` on this host. Re-running the same bounded helper under Windows
PowerShell produced the result above. Repeated attempts were stopped to avoid
turning an ambiguous harness condition into a product verdict.

## Interpretation

This run does **not** prove a recovery defect: it never reached the precondition
of a durable dirty session. It also does not satisfy the packaged recovery
gate. The transaction-level frontend and Rust tests remain valid, but release
GO still requires an end-to-end forced-crash run on a host where the official
launcher enters AUTOTEST, followed by recovery through the exact packaged
candidate.

## Required rerun

1. Use PowerShell 7 and the exact release-SHA smoke launcher.
2. Assert the first successful turn, durable session directory, binding, and
   `cleanExit=false` marker before termination.
3. Launch the installed, signed candidate with the same isolated state.
4. Verify the visible recovery prompt, exact session identity and history, a
   retryable failure path, and `cleanExit=true` only after successful restore or
   explicit dismissal.
5. Preserve process output, marker transitions, screenshots, and artifact
   hashes in the release evidence bundle.
