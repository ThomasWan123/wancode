# v0.23.5 Work session lifecycle evidence

Status: implementation evidence for independent review. This document does not
authorize a merge, version bump, tag, Release, or asset upload.

## Incident and root cause

Reproduction: in Work, create a new session and immediately rename it. The UI
reported `Invalid request: session not found: <id>`.

The failure crossed three identity domains that must remain distinct:

1. Work's visible folder is the user's source folder.
2. Work sessions are stored under WanCode's internal durable Work workspace.
3. A session-list action targets one selected stored session ID.

The previous UI only cleared its local transcript for **New session**. Rename or
delete then started an unrelated blank engine session, passed the visible source
folder as the session-store cwd, and the extension boundary injected the live
session ID next to the selected target ID. The backend therefore searched the
wrong store with ambiguous identity.

## Fix contract

- **New session is real:** it starts a backend Work session under the existing
  durable Work workspace ID.
- **Actions are target-bound:** when no engine is live, rename/delete resumes the
  selected session instead of minting an unrelated blank session.
- **Cwd is authoritative:** search/rename/delete use the live engine handle cwd;
  the visible folder is never trusted as the session-store location.
- **One target identity:** explicit rename/delete requests keep the selected
  `sessionId` and do not receive a second live `session_id` alias.
- **Transactional UI:** a failed delete leaves the active session and transcript
  intact; successful deletion clears UI state only for the deleted active session.
- **Start serialization:** New/Rename/Delete controls are disabled while an
  engine handle is being replaced.
- **Reverse direction:** Chat and Code recovery do not receive a Work workspace ID.

## Tests proven capable of failing

- RED-first: before the UI guard was added, the WorkDesk test observed that New
  session remained enabled during engine replacement and failed.
- Mutation: replacing runtime cwd with the visible source folder made four
  lifecycle tests fail, including the 50-cycle heavy-user probe. Restoring the
  production rule returned them to green.
- Positive controls: ordinary extension calls still receive the live ID aliases;
  only explicit rename/delete target operations suppress the conflicting alias.

## Honest limitations

- Packaged installer coordinate-click GUI is **NOT-RUN** on this head. The local
  Windows helper could not target the custom debug window after launch. The real
  Windows custom-protocol backend and persistence path is covered by S7, but this
  is not represented as a packaged GUI pass.
- A strict `cargo clippy -p wancode --lib -- -D warnings` is **NOT-PASS** because
  unchanged vendored `xai-crash-handler` triggers `clippy::unnecessary_cast`.
  No warning in this change is being hidden, and this gate is not claimed green.
- No real model/API call is needed for the lifecycle bug, so the Work smoke is
  deliberately zero-API and deterministic.
