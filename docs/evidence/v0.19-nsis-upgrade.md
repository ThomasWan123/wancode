Date: 2026-08-09

The baseline engine was materialized from the locked commit and verified against
HEAD, the three registered artifact hashes, the exact porcelain set, and the
effective-tree digest before packaging.

## Procedure and evidence

1. Silently installed the exact-tag baseline to a disposable application path.
   Installation returned exit 0 and created `wancode.exe` plus `uninstall.exe`.
2. Created isolated `APPDATA`, `LOCALAPPDATA`, `GROK_HOME`, and
   `WEBVIEW2_USER_DATA_FOLDER` roots outside the application directory. Each root
   received a unique content-hashed sentinel.
3. Launched the installed baseline. It exposed a native main window after 388 ms
   and created 26 isolated-profile files.
4. Silently installed the remediation package to the same application path.
   Installation returned exit 0. The installed executable hash changed from
   `C35F221643E4C2D8BFD5018CF25EE2CCB6C9B9E6F941EFD2D5EEAC547DE7E090`
   to `CA82DA495B7FCEFF2A4779BB11C51C377B33221645BCDAC4B2CEC550383A4745`,
   proving the binary was replaced rather than the old application being reused.
5. Relaunched the remediation executable with the same four isolated roots. It
   exposed a native main window after 366 ms. All four sentinel files remained
   present with byte-identical SHA-256 values; the profile grew to 33 files as
   WebView2 updated its runtime state.
6. Silently uninstalled. Uninstall returned exit 0, removed the application
   directory, retained the external profile and all four sentinels, and left zero
   WanCode processes.

## Scope limit

This is a same-version installer replacement and profile-preservation test. The
zero-model first-run path did not create provider configuration, sessions, or
credentials, so this evidence **does not** prove business-data schema migration,
credential continuity, rollback, or an upgrade from v0.18. Those remain release
gates.
