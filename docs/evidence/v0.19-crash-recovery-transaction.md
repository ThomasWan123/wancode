# v0.19 Crash Recovery Transaction Evidence

Date: 2026-08-09

Product branch: `fix/v019-hermetic-worktree-snapshot`

Product head: `f324a86`

## Finding

The restore action acknowledged and removed the dirty-session marker before it
attempted to restore the session. If restoration failed, the application lost
the only recovery pointer and offered no safe retry. Dismissal also cleared the
visible prompt before acknowledgement was known to have reached disk.

The backend had a second crash window: marker writes used a non-atomic file
write, ignored errors, and occurred after the session handle was exposed. A
usable session could therefore exist without a durable recovery pointer after
a disk-full, permission, or process-crash event.

## Required transaction contract

1. Restore never acknowledges the old marker before session restoration.
2. A successful session start writes the active dirty marker itself.
3. A failed restore preserves the old marker and keeps the recovery action
   visible for retry.
4. Dismissal clears the UI only after durable acknowledgement succeeds.
5. Session publication occurs only after the dirty marker has been written
   atomically; a marker failure cancels startup and returns a structured error.
6. Corrupt marker bytes are preserved and reported instead of being silently
   replaced or acknowledged.

## Fix and evidence

Commit `f324a86` implements the transaction in the frontend and Rust backend.

- Frontend: three focused contracts cover successful restore without early
  acknowledgement, failed restore with the marker preserved, and visible
  acknowledgement failure on dismissal.
- Rust: five focused contracts cover atomic marker creation, visible write
  failure with no target file, atomic acknowledgement with identity
  preservation, corrupt-marker preservation, and idempotent missing-marker
  acknowledgement.
- Mutation: temporarily acknowledging before restore made two of the three
  frontend contracts fail; restoring the correct ordering returned the suite
  to green.
- Full frontend baseline: 12 files, 58 tests passed; TypeScript typecheck
  passed.
- Full Rust library baseline: 180 tests passed, zero failed, with one dedicated
  plugin lifecycle probe ignored by design.
- WanCode Clippy: `cargo clippy --locked -p wancode --lib --no-deps -- -D
  warnings` passed.

## Environment qualification

The first full Rust run exposed one test-environment issue rather than a
product failure: the worktree snapshot fixture could not initialize a Git
repository under the Windows user temporary directory because that directory
had been created under a different sandbox identity. The exact test passed
when `TEMP` and `TMP` were set to an isolated workspace directory. The full
suite then passed 180/180 under isolated `TEMP`, `TMP`, and `GROK_HOME` roots.

Six stale `wancode-wtsnap-*` directories from earlier interrupted runs were
validated by exact prefix and absolute parent, then removed. The fixture should
continue using an isolated temporary root in automation so host ACL history
cannot affect the result.

## Remaining limitation

This evidence proves the transaction and failure semantics at the unit layer.
A packaged, forced-crash restore journey remains required before release GO.
