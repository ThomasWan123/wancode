# v0.19 Modal Accessibility Inventory

Date: 2026-08-09  
Fix commit: `4203438`  
Environment: rebuilt Windows debug candidate plus component contracts

## Inventory result

After onboarding was fixed independently, nine remaining overlay types still
used plain modal containers without one enforceable focus contract:

- Settings
- Git
- background tasks and subagents
- command palette
- rewind checkpoints
- skill editor
- folder trust
- engine question
- plan approval

The last three are safety-sensitive because the engine is waiting for an answer.
Closing only the visual layer would leave the request unresolved or risk a
fail-open interpretation.

## Shared contract

`ModalDialog` now provides:

- named `role="dialog"` and `aria-modal="true"` semantics;
- initial focus inside the dialog;
- optional safe-default autofocus for reject/cancel actions;
- Tab and Shift+Tab focus wrapping;
- Escape routing through the caller's real cancellation callback; and
- focus restoration to the control that opened the dialog.

Every `modal-mask` overlay now uses this contract, except onboarding, whose
equivalent behavior was already verified in `2167d07`.

## Automated safety evidence

- shared semantic and bidirectional focus-loop tests;
- safe-default autofocus test;
- folder-trust Escape invokes `agent_trust_respond` with `trust:false`;
- engine-question Escape invokes the production cancel callback; and
- plan-approval Escape invokes `respondPlan("cancelled")`.

The current frontend baseline is 55/55 with no unhandled test errors. An early
mock returned `undefined` instead of a Promise and produced a post-test
rejection; the run was rejected and the mock corrected before evidence was
accepted.

## Desktop evidence

The rebuilt Settings overlay was selected as the representative real desktop
journey:

- Windows UI Automation exposed `dialog: Settings`;
- Shift+Tab from the first navigation action wrapped to Close;
- Tab from Close wrapped back to General;
- Escape closed the dialog; and
- focus visibly returned to the Settings trigger.

The disposable WebView2 profile was removed after exit. Screen-reader speech
output, IME composition, and display-scale coverage remain outside this result.
