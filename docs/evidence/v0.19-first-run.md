# v0.19 Isolated First-Run Evidence

Date: 2026-08-09  
Executable: local debug remediation candidate  
Environment: Windows 11, Chinese system locale

## Isolation contract

A first attempt isolated `APPDATA`, `LOCALAPPDATA`, and `GROK_HOME` but still
displayed a previously used workspace. The retained state came from WebView2's
user-data store. The valid clean-profile run therefore isolated all four roots:

- `APPDATA`
- `LOCALAPPDATA`
- `GROK_HOME`
- `WEBVIEW2_USER_DATA_FOLDER`

This is a test-harness requirement: isolating only the backend data root does
not prove a clean frontend profile.

## Observed result

- Native WanCode window opened.
- UI followed the system language (Simplified Chinese).
- Welcome wizard was visible with GLM Coding Plan, Zhipu Open Platform,
  DeepSeek, and custom OpenAI-compatible endpoint choices.
- No previous sessions or workspace were present.
- The empty state offered an explicit project-folder action.
- The send action was disabled before a workspace/model was ready.
- Choosing the deferral action closed the wizard without creating a model or
  workspace.
- Restarting the same isolated profile showed the wizard again. Source review
  confirms this is the current zero-model invariant: deferral is process-local,
  and startup reopens onboarding while `model_list` is empty.

## Scope and remaining risk

This is a partial first-run pass. No API key was entered or transmitted, so the
connection-test, save-on-success, failed-key handling, and successful transition
to a configured provider remain untested in this journey. Those steps must be
run with a disposable test credential before release sign-off.

The two disposable profile directories were deleted after the app exited.
