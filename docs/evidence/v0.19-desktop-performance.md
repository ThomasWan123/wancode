# WanCode v0.19 desktop startup baseline

> Date: 2026-08-09  
> Platform: Windows 11 x64  
> Candidate branch: `fix/v019-hermetic-worktree-snapshot`  
> Candidate executable: debug build, unsigned  
> Method: three sequential process launches; poll the main window handle every
> 100 ms, sample the parent process five seconds after window readiness, then
> terminate it before the next launch

## Results

| Run | Window ready | Working set after 5 s | Private memory | CPU time | Threads |
|---:|---:|---:|---:|---:|---:|
| 1 | 1,966 ms | 88.1 MB | 19.8 MB | 1.89 s | 54 |
| 2 | 125 ms | 87.9 MB | 19.4 MB | 1.64 s | 54 |
| 3 | 125 ms | 88.6 MB | 20.0 MB | 1.45 s | 54 |

Median window-ready time was **125 ms** and the maximum was **1,966 ms**.
Mean sampled working set was **88.2 MB**.

## Interpretation and limits

- Run 1 is the closest observation to a cold application start in this series;
  runs 2 and 3 are warm starts and may benefit from operating-system and
  WebView2 caches.
- The executable is a debug candidate, so these numbers are a regression
  baseline, not a release performance claim or target.
- The measurement proves that the parent process exposed a native main window;
  it does not prove first-contentful paint, interactive readiness, model
  readiness, or child-process resource totals.
- A release GO decision still needs a signed release build on clean Windows 10
  and 11 systems, cold boot sampling, WebView2 child-process accounting, and a
  task-level latency distribution.
