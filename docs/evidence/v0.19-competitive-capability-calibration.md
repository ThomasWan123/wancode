# v0.19 Competitive Capability Calibration

> Retrieved: 2026-08-09  
> Purpose: define eligible comparison scenarios before executing WanCode, Codex, and Claude Code runs  
> Result type: documentation calibration only; no competitive score is awarded here

## 1. Method

Only first-party OpenAI and Anthropic sources were used. A documented capability makes a
scenario eligible for testing, but it does not prove that the installed version, account,
model, operating system, or permission configuration can execute it. Runtime evidence must
record the exact product surface and version.

## 2. Codex capability baseline

The official Codex app material supports testing these dimensions:

- parallel agent threads and distinct work streams;
- built-in worktree isolation;
- diff review and feedback within a task;
- skills and automations;
- system-level sandboxing and configurable permissions;
- Windows availability;
- long-horizon repository work, context compaction, refactors, migrations, tool use, and
  screenshot interpretation.

Sources:

- [Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/)
- [Introducing GPT-5.2-Codex](https://openai.com/index/introducing-gpt-5-2-codex/)
- [Codex is generally available](https://openai.com/index/codex-now-generally-available/)

These claims map to capability probes C01, C02, C03, C05, C07, and C08 in the quality plan.
They do not establish Codex scores for B01–B10.

## 3. Claude Code capability baseline

The official Claude Code material supports testing these dimensions:

- Windows execution through Git Bash or WSL;
- interactive and non-interactive prompt execution;
- text, JSON, and streaming JSON output;
- continuation and resume;
- allowed and disallowed tool controls;
- permission modes and maximum-turn controls;
- verbose diagnostics;
- MCP integration.

Sources:

- [Claude Code setup](https://docs.anthropic.com/en/docs/claude-code/getting-started)
- [Claude Code CLI reference](https://docs.anthropic.com/en/docs/claude-code/cli-usage)
- [Connect Claude Code to tools via MCP](https://docs.anthropic.com/en/docs/mcp)

These claims map to capability probes C02, C03, C04, C06, and C08. Hooks, subagents,
computer use, checkpoints, background work, and cloud delivery are not assumed by this
calibration; add them only when the exact installed surface exposes them and a current
first-party source is attached to the run.

## 4. WanCode differentiation under test

WanCode is not scored on competitor feature count. The benchmark gives extra scrutiny to
its declared product strengths:

1. provider identity and routing across GLM, DeepSeek, and compatible endpoints;
2. immutable Chat/Code session identity with fail-closed restoration;
3. lifetime isolation of Chat from plugins, hooks, MCP, LSP, skills, and subagents;
4. Windows-native process cleanup, packaged lifecycle, recovery, and update integrity;
5. auditable local Git/worktree, diff, review, and rewind behavior.

Every negative isolation test requires an activated Code positive control. A zero-event
result is invalid when the fixture did not first prove that the same capability works in an
allowed session.

## 6. Required run manifest

Each competitor run must record:

- product, surface, build/version, date, and operating mode;
- model and reasoning setting when visible;
- authenticated account class without credentials or secrets;
- repository commit, fixture hash, starting Git status, and worktree/sandbox mode;
- permission mode, allowed/disallowed tools, MCP configuration, and network state;
- prompt, acceptance tests, start/end time, retries, interventions, final diff, logs, and
  cleanup result;
- unsupported or unavailable capabilities as `NOT-ELIGIBLE`, and environmental blockers as
  `BLOCKED`.

The same fixture, acceptance tests, and scoring rubric must be used across products. Any
deviation is disclosed beside the score and prevents a direct winner claim.
