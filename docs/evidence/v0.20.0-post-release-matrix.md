## 1. Review findings

### P1-1 — Rust dependency advisory gate is red

`cargo audit` against a locally materialized RustSec advisory database returned
exit code 1. The shared locked graph contains 11 vulnerable package-version
matches across seven unique advisories. Ten matches are present in the
`x86_64-pc-windows-msvc` resolution; `quinn-proto 0.11.14` is the only reported
match excluded from that target resolution.

| Advisory | Locked package(s) | Fixed release | Windows resolution |
|---|---|---|---|
| RUSTSEC-2026-0204 | `crossbeam-epoch 0.9.18` | `>=0.9.20` | yes |
| RUSTSEC-2026-0258 | `h2 0.4.15` | `>=0.4.16` | yes |
| RUSTSEC-2026-0194 | `quick-xml 0.37.5`, `0.38.3`, `0.39.4` | `>=0.41.0` | yes |
| RUSTSEC-2026-0195 | `quick-xml 0.37.5`, `0.38.3`, `0.39.4` | `>=0.41.0` | yes |
| RUSTSEC-2026-0185 | `quinn-proto 0.11.14` | `>=0.11.15` | no |
| RUSTSEC-2023-0071 | `rsa 0.9.10` | no patched release recorded | yes |
| RUSTSEC-2026-0257 | `webbrowser 1.0.6` | `>=1.2.2` | yes |

RustSec additionally reported 25 unmaintained and 15 unsound package-version
warnings. These counts describe the locked dependency graph and do not prove
that every vulnerable operation is reachable from WanCode. They nevertheless
prevent a clean dependency-security verdict and require a dedicated dependency
remediation change plus a rebuilt release.

### P2-1 — PR #68 originally had line-ending-only diff noise

The REST-created branch stored several text blobs with CRLF while `main` uses
LF, inflating the displayed change count. The post-audit branch update must
normalize all edited text blobs to LF before requesting the external review.

## 4. Updater chaos matrix

The deterministic cases below call the same production decision helper used by
the updater download loop. Minisign verification remains owned by the Tauri
updater plugin; tests inject the plugin's verified/error outcome rather than
imitating cryptography.

| Case | Expected invariant | Result |
|---|---|---|
| Origin valid | accept verified non-empty bytes | PASS |
| Origin fails, mirror valid | ledger origin failure, accept mirror | PASS |
| Zero-byte download | reject and ledger `download-empty` | PASS |
| Defensive empty verified variant | reject and ledger `download-empty` | PASS |
| Truncated bytes | reject plugin verification error | PASS |
| Corrupt/signature mismatch | reject plugin verification error | PASS |
| Download timeout | reject and ledger bounded timeout | PASS |
| Stale manifest | exclude from highest-version group | PASS |
| Both sources fail | return complete structured failure ledger | PASS |
| Forged high version with invalid signature | fail closed; never downgrade to lower valid bytes | PASS |
| Same-version sources | stop after first verified source | PASS |
| Empty candidate set | no selection | PASS |
| Highest-version tie priority | preserve configured source order | PASS |

Focused result: 13/13 tests passed. Mutation proof changed the empty-download
branch to accept bytes; `zero_byte_is_ledgered_and_never_accepted` failed, then
the production branch was restored and 13/13 passed again. This demonstrates
that the key fail-closed assertion detects the relevant regression.

Live hostile HTTP fixtures for zero-byte, truncation, corruption, stale
manifest, and timeout remain `NOT-RUN`; the deterministic matrix must not be
described as complete transport-level chaos coverage.
