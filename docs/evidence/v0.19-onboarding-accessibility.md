# v0.19 Onboarding Accessibility Evidence

Date: 2026-08-09  
Fix commit: `2167d07`  
Environment: rebuilt Windows debug candidate, isolated WebView2 profile

## Failure reproduced

The zero-model welcome overlay used plain `div` containers without dialog
semantics or focus management. On the real desktop candidate:

- accessibility inspection exposed no dialog node;
- initial focus remained on the WebView container; and
- the first Tab visibly focused the background Chat surface toggle behind the
  modal mask.

This was a keyboard isolation failure, not merely missing metadata.

## Remediation

- `role="dialog"` and `aria-modal="true"`
- accessible name through `aria-labelledby`
- initial focus on the first provider action
- Tab and Shift+Tab wrap between the first and last dialog controls
- Escape dismissal

Three component contracts cover semantics, both focus-loop directions, the
background non-focus condition, and Escape dismissal. The frontend baseline is
now 50/50 tests.

## Desktop verification

After rebuilding the Tauri debug executable:

- Windows UI Automation exposed `dialog: Welcome to WanCode`;
- the GLM Coding Plan button had the visible initial focus ring;
- Shift+Tab moved from the first control to the final deferral action;
- Tab moved from the final action back to the first control; and
- Escape removed the dialog.

The disposable profile was deleted after the app exited. Screen-reader speech
output and the remaining modal inventory are still open release-test work.
