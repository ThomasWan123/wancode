# WanCode v0.19 display-scale evidence

Date: 2026-08-09  
Candidate: `0b86c77bce151fd447f23c47e3b28d3986d54577` release executable  
Host scale: **150%** (`AppliedDPI=144`)  
Result: **PARTIAL PASS**

## Scope

The exact unsigned release executable was inspected through Windows Graphics
Capture and UI Automation at the host's existing 150% display scale. System
display settings were not changed. The captured WanCode client area was
1103×791 logical pixels.

## Observations

- The title bar, Chat/Code surface switch, connection state, toolbar, recovery
  banner, sidebar, recent sessions, workspace indicator, model selector,
  permission mode, and composer were simultaneously visible.
- The recovery banner retained distinct visible `Restore` and `Dismiss`
  controls and did not cover the session surface controls.
- After recovery, the banner disappeared and the full composer/footer remained
  visible without horizontal scrolling or clipped primary actions.
- UI Automation exposed the surface toggles, toolbar controls, recovery
  actions, navigation, recents, workspace, model selector, permission mode,
  terminal, and send control with roles or descriptions.
- The `Restore` action completed at 150% scale and the application remained
  keyboard-addressable and responsive.

## Limits

This is a core-layout and control-availability check, not a complete 150%
journey. Dense diffs, terminal output, long localization strings, image input,
and all modal variants were not exercised in this run. The 100% and 200%
release-candidate matrix remains untested, and no screen-reader speech claim is
made.
