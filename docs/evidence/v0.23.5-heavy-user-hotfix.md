# v0.23.5 heavy-user hotfix evidence

## Scope

This patch closes the session-lifecycle failures found while exercising the
published v0.23.5 build as a heavy user. It deliberately does not change the
version, tag, updater manifest, or release assets.

## Closed findings

| ID | Finding | Closure |
| --- | --- | --- |
| HU-01 | Work startup could be started by two effects, producing a serial 30-45 second fallback chain. | The initial auto-start no longer owns Work; the persisted Work resume flow is the sole owner. |
| HU-02 | A completed prompt could leave the composer busy forever if a UI turn-end event was missed. | The primary `agent_prompt` promise now provides a second, idempotent terminal path; queued turns remain queue-owned. |
| HU-03 | Switching to an uncached Chat/Code surface left the previous surface's backend lease active. | The surface ref changes synchronously and uncached Chat/Code switches immediately start their own backend session. |
| HU-04 | Session changes could show tasks, subagents, worktrees, scheduler state, MCP state, or busy state from the previous session. | All session-scoped UI state is cleared before a non-preserving start. |
| HU-05 | ACP initialize/authenticate could hold `Starting...` without a wall-clock bound. | Initialize and authenticate each have a 15-second fail-visible timeout and cancel the abandoned attempt. |
| HU-06 | Compact context could send both `session_id` and `sessionId`, which alias to the same engine field. | Compact sends only the canonical snake-case identity. |
| HU-07 | Branch-from-here used the visible Work folder rather than the live engine session store. | Fork source/new cwd now comes from the live handle. |
| HU-08 | WebView2 dark mode could render selected surface/session labels white on white. | Explicit high-specificity dark selected-state colors were added. |

## Honest GUI boundary

Interactive control of the newly isolated executable is **NOT-RUN**. The local
desktop-control broker routed a same-name launch to an older registered WanCode
copy; launching the uniquely named isolated copy then required a broker approval
that expired. The process was stopped and no older UI was counted as evidence for
this patch. Packaging and isolated installation are green, but the independent
review should still run the packaged GUI scenarios before merge.

Required independent packaged-GUI scenarios:

1. Switch Chat -> Code -> Work -> Chat with no cached sessions; each surface must
   become usable without inheriting the previous lease or busy state.
2. Start Work from a remembered folder; only one startup chain may run and any
   handshake stall must end with a visible error within the bounded intervals.
3. Complete one real prompt on each surface and confirm Send always returns from
   busy state.
4. Run Compact context and Branch from here; there must be no duplicate-session
   decode error and the fork must resume beside the live session store.
5. Toggle dark mode and confirm selected surface and selected session text remain
   readable.
