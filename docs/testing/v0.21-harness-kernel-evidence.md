# v0.21 Harness Kernel evidence

Status date: 2026-08-23

This file records the evidence for the first implementation slice described in
`docs/design/v0.21-harness-kernel-roadmap.md`. It is an engineering gate, not a
release announcement. Cowork orchestration and scanned-document OCR remain
gated until their later work packages meet their own gates.

## Implemented boundary

- append-only, fsync-backed Execution Ledger v1;
- strict completed-record parsing and fail-closed future/corrupt schemas;
- preservation of a crash-truncated final fragment;
- automatic interrupted-turn cancellation reconstruction on reopen;
- field-level redaction and hashes for prompt, tool input/output and provider
  request evidence;
- session, turn, provider, approval, tool and resource lifecycle projection;
- immutable CapabilityLease issued before a session handle is published;
- lease continuity checks on prompts and live ACP events;
- Surface-specific roots and MCP inheritance:
  - Code: workspace read/write and configured MCP inheritance;
  - Work: staged workspace read-only, no configured MCP inheritance;
  - Chat: no filesystem roots and no configured MCP inheritance;
  - Cowork: still gated;
- lease-bound Job resource ownership and release on terminal, replacement and
  clean application close;
- lease-bound Terminal handles at every host extension entry: creation is
  registered, list results are owner-filtered, use/reconnect/input is denied to
  siblings and unregistered IDs, and release/kill consumes ownership;
- single-use approval receipts bound to the live session, immutable lease,
  exact tool call/action fingerprint and engine-advertised option IDs; session
  replacement cancels every outstanding receipt;
- deterministic bounded scheduler kernel with parallel reads, exclusive write
  barriers and synthetic cancellation terminals;
- production engine source at
  `grok-build@9e9adb62d3251c5cdafbbfe4dcc17ea83b411910` contains a four-read
  rolling window and mutation barrier. Compilation and migration evidence cover
  that source; a delayed-body engine integration probe remains explicitly
  NOT-RUN and no runtime timing claim is made by this slice;
- GitHub's Git Data API normalized the commit timezone to UTC. The published
  object `9e9adb62` and locally checked object `18abccf9` therefore have
  different commit IDs but the same byte-identical tree
  `a085c4b6b104cfa9e19a3a562a8a5228fc731289`;
- GLM, DeepSeek and unknown/custom provider profile evidence is bound to live
  session start, model-route changes and request fingerprints. The v0.21 fields
  describing tool presentation and read concurrency are recommendations only;
  production engine tuning from those fields remains out of scope;
- terminal ownership commit failure cancels and removes the exact live session
  after a best-effort engine kill, then releases all host bindings, so an
  unregistered terminal cannot continue behind a usable session;
- duplicate execution event IDs are checked by the same fail-closed predicate
  used before `agent_prompt` accepts a turn and by Settings diagnostics;
- read-only, redacted execution-integrity summary in Settings > About.

ACP `ToolKind` is presentation metadata and is not treated as a secure host tool
identity. Actual Chat/Work tool-set restriction remains enforced by the engine
AgentDefinition profiles. The rolling scheduler now runs at the engine's real
`execute_tool_calls` entry and classifies from the engine-owned
`PreparedToolCall::is_read_only`, rather than trusting ACP presentation data.

The prior bootstrap produced `3372676f...` after its implicit first checkout;
the first migration-audit repair still inherited the caller's checkout policy
and registered `70e4345c...`. Bootstrap and both audit materializers now clone
without checkout and materialize the pinned commit exactly once with
`core.autocrlf=false`; the manifest records the machine-independent raw tree
`0365143a...`.

The competition additions include:

- eight concurrent ledger writers, 400 durable records, contiguous sequence and
  no duplicate event IDs;
- eight simultaneous claims of one Job resource, exactly one winner;
- sibling/unregistered terminal IDs removed from list projection and rejected
  by the same registry used by live extension dispatch;
- stale session/lease approval receipts and forged option IDs fail closed;
- 100 scheduled calls with four-way read concurrency, ten exclusive mutation
  barriers and exactly one terminal per call;
- repeated cancellation producing no duplicate synthetic terminals.
- provider profile identity survives session start and route changes without a
  fail-open `None` state;
- seeded duplicate IDs reach the actual prompt integrity predicate, with an
  empty-diagnostics positive control;
- terminal ownership commit failure cancels the engine session and reads back
  an empty ownership registry.

## Chaos and negative coverage present

- completed-line corruption and unknown fields block execution;
- future schema and non-monotonic sequence are distinct failures;
- truncated final line is preserved and sequence resumes correctly;
- valid final line without newline is normalized;
- interrupted turn receives one recovered terminal event;
- secret-like identities and URL/query tool names are rejected;
- raw prompt, image, tool argument and tool output bodies are absent from the
  ledger;
- malformed PDF, parser abort, hang, output flood, missing source, unavailable
  Job Object and worker wait failure are contained;
- staged DOCX/PDF tampering is rejected before model context construction;
- image-only PDF reports the truthful OCR-not-supported boundary;
- Work/Chat local-extension and MCP isolation fail closed.

## Gates still open

1. Add a deterministic engine integration probe with delayed real read and
   mutation tool bodies; compile and pure competition coverage are green, but
   timing/barrier evidence still needs to be archived.
2. Add deterministic disk-full/write-denied fault injection for every ledger
   fsync boundary.
3. Run packaged-GUI loops on supported Win11 and final Win10 images, including
   IME, 200% scaling, screen-reader names and reduced motion.
4. Run model-bound GLM/DeepSeek live canaries with a cost budget before enabling
   any non-native tool presentation.
5. Complete Cowork child-agent leasing, cancellation and worktree cleanup before
   changing the Cowork launch gate.
6. Complete OCR worker isolation, language packs and citation provenance before
   accepting scanned documents.

No tag, release, updater manifest or asset upload is authorized by this evidence.
