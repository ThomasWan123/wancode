# `local_extensions_disabled` 接口草案（v0.19 · G26 唯一安全例外）

> 状态：**第七版（实现复核落实：三态查询 / null 拒绝 / 条件式 reload / 测试架构裁决，白名单 18+3）**。依据 = 设计稿第五版 §1.3 的裁决与
> 2c 探针实证（`docs/evidence/v019-2c-fanout-probe.log`）。
> 本文锁定边界后再开 fork 主题 PR。

## 0. 接口语义（第四版收敛）

`local_extensions_disabled = true` 的会话**只能使用内建工具**，以下外部
扩展通道**全部归零**：

| 通道 | 范围 |
|---|---|
| plugins | 会话本地 registry 恒 `None`（初始/broadcast/snapshot 三层） |
| **所有 hooks** | 磁盘 hooks、plugin hooks、`AgentDefinition.hooks`、New 的 client hooks、驻留 Load 的 `reconnect_client_hooks`（五条，定位表 §D） |
| **所有非内建 MCP** | plugin MCP、**managed MCP**、请求 `mcp_servers`、`_meta["x.ai/mcp/servers"]`（四条的**会话数据面连接**在引擎侧归零；managed 配置的 agent 级控制面列举不属于会话策略，定位表 §E） |
| **所有 LSP** | 插件贡献 **+ 用户 `~/.grok/lsp.json` + 项目 `.grok/lsp.json`**——LSP 起后台进程且读工作区，与零文件面冲突（定位表 §A） |
| plugin skills / commands | 随本地 registry 归零；slash 三命令另加兜底拒绝 |
| **派生子代理** | 严格继承策略位；共享 plugin registry、`AgentDefinition.hooks`、`AgentDefinition.mcp_servers`（含 Inline）三源归零（定位表 §I） |

Code（默认 `false`）路径逐项不变。落点逐条见
[注入面定位表](v0.19-injection-surface-map.md)。

## 1. wire 字段位置与默认值（第三版：**推翻第二版归宿**）

### 1.0 第二版的 P0 错误与实证

第二版把标志放进 `StartupHints`，理由是"它已从 meta 解析、存在 actor 上、
只读"。**这是错的**——实测 `spawn_and_register_session`
（`agent_ops.rs:2864`）解析 startupHints 用的是 `init.meta`，而 `init`
来自 `self.initialize_request`（`acp_agent.rs:818` 取自 `OnceCell`，
`acp_agent.rs:141` 每连接只 `set` 一次）：

```rust
// acp_agent.rs:818 —— 连接级，不是会话级
let init = self.initialize_request.get().ok_or_else(|| …)?;
// agent_ops.rs:2972
let startup_hints = init.meta.as_ref().and_then(|m| m.get("startupHints"))…
```

**后果**：`StartupHints` 是**每连接一份**。而本项目的真实拓扑正是
**单连接内 Chat + Code 并存**（2c 探针即如此，生产 WanCode 也共用一个
引擎连接）——放这里会导致同连接两个会话共享同一个值：要么两层都禁用
（Code 废掉），要么都不禁用（Chat 裸奔）。按第二版实现出来的接口
**在真实拓扑下根本不成立**。

### 1.1 第三版归宿：会话级 `session_meta`

`spawn_and_register_session` **同时**收到 `init`（连接级）与
`session_meta`（本次 New/Load 的 meta）；后者已被多处按会话消费：
`reject_direct_hub_cloud_meta(session_meta)`（:2899）、
`parse_agent_profile_from_meta(session_meta)`（:3181）。标志走它。

**wire**：`_meta["x.ai/localExtensionsDisabled"] = true`（顶层键，与
`x.ai/mcp/servers`、`agentProfile` 同级；不塞进 `startupHints`，避免与
连接级语义混淆）。

```rust
// agent_ops.rs：与既有 session_meta 解析并列
let local_extensions_disabled =
    parse_local_extensions_disabled(session_meta)?;   // 类型错误 → Err（T11）
```

| 路径 | 载体 | 说明 |
|---|---|---|
| 新建 | `NewSessionRequest._meta["x.ai/localExtensionsDisabled"]` | Chat 显式传 `true` |
| 恢复 | `LoadSessionRequest._meta["x.ai/localExtensionsDisabled"]` | 客户端按 sidecar binding 重传 |

默认（键缺失）= `false`：其他客户端与 Code 路径逐字保持现状。

> 引擎**不持久化**该标志（沿用第二版裁决）：恢复时由客户端按
> `SurfaceBinding.surface_kind == Chat` 重传，与 `EffectiveSurfacePolicy`
> 每次派生同源；漏传由握手回显（§3）兜住。

## 2. 会话内不可变锁存（**第六版：改定存储位置**）

### 2.1 为什么不给 `SessionActor` 加字段

第三版写的是「`SessionActor` +1 字段」。**实测否决**：`SessionActor { … }`
字面量全仓 **25 处、分布在 14 个测试文件**（`acp_session_tests/*` 与
`compaction.rs` 内联测试）。加一个字段会强制修改这 14 个文件——机械改动
淹没本批的安全 diff，也让"白名单外零改动"的约束形同虚设。

### 2.2 改定方案：三处存储，同一构造点写入

| 存储位 | 用途 | 读取方式 |
|---|---|---|
| `SessionHandle.local_extensions_disabled: bool` | broadcast 遍历（`mod.rs:2120` 的闭包只拿得到 handle）、扩展端点按 `session_id` 查表、驻留 Load 冲突比较、握手取值 | **无锁直读** |
| `AgentRebuildSpec.local_extensions_disabled: bool` | actor 侧存储；经既有 `SessionActor.rebuild_spec`（`acp_session.rs:1026`）读取 | `self.rebuild_spec.local_extensions_disabled` |
| `SubagentSpawnContext` / `SubagentValidationContext` 各 +1 字段 | 子代理显式继承（§I） | 直读 |

选 `AgentRebuildSpec` 的两个理由：

1. **零测试改动**——其字面量实测仅 2 处：`spawn.rs:820` 与
   `agent_rebuild.rs:375` 的 `#[cfg(test)] test_rebuild_spec_default()`，
   而那 14 个测试文件正是共用后者这个 stub；
2. **重建不丢**——`AgentRebuildSpec` 是模型切换等**会话重建**路径的规格
   来源，策略位放这里意味着任何重建都携带同一策略，不需要额外记忆。

**一致性要求（T19）**：`spawn.rs` 在**同一构造点**写入 handle 与
rebuild spec，二者必须相等；测试须显式断言这一点——两处存储是为了读取
便利，不是两个事实源。

### 2.4 父会话缺失时的 fail-closed（第六版新增，T21）

`build_subagent_validation_context`（`subagent_coordinator.rs:259`）的
doc comment 明写 **"tolerates evicted parent sessions (returns built-in
defaults + warns)"**：`parent_cwd` 走 `unwrap_or_default()`、
`allowed_subagent_types` 走 `None`，而 `plugin_registry:
self.plugin_registry_handle.snapshot()`（`:280`）是**无条件**的。

**后果**：父会话被驱逐后，策略位**无从读取**。若按"读不到就默认 false"
实现，validation context 会继续交出**共享 plugin registry**——驱逐竞态
直接重新暴露插件 agent。这是典型的 fail-open。

**裁决（fail-closed）**：

| 父会话状态 | 处置 |
|---|---|
| 存在 | **严格继承**其锁存值 |
| 缺失 | **不得回落 `false`**。`plugin_registry` 必须为 `None`；或直接返回 `Unavailable` 让调用方重试/放弃 |

即：**读不到策略位 ⇒ 按最严策略处理**，与 §3 的握手硬门同向（宁可
误拒，不可静默放行）。现有 `warn_on_missing_parent_session_for_validate_type`
的告警保留。

同理适用于 `try_build_subagent_spawn_context`（可竞态的只读调用方，
如 `DescribeType`）；`build_subagent_spawn_context` 本身对缺失父会话
`panic`（真实不变量违反），不需要额外处置。

### 2.3 不可变性

- 只在 actor 构造时写入；不新增 setter；`SessionCommand` 不加切换变体。
- 恢复重建：Load 走同一 `spawn_and_register_session`；**若 session 已有
  驻留 actor**，先比较 `SessionHandle` 上的锁存值（§3 时序），不一致即
  拒绝，不重建、不就地改。

## 3. 应用确认握手（防静默 fail-open）

引擎在**两个响应**里回显，位置与既有 meta 同处：

| 响应 | 位置 | 值 |
|---|---|---|
| `NewSessionResponse` | `.meta["localExtensionsDisabledApplied"]`（**`acp_agent.rs:1251`**） | 请求为 true 且策略已装配 → `true` |
| `LoadSessionResponse` | 同上（**`acp_agent.rs:2125`** 的 `response_meta` 构造处） | 同上 |

**取值来源（T12）**：`applied` 必须读**实际锁存状态**——`SessionHandle`
上的锁存值；**不得**把请求值原样回显，否则装配失败时会给出假确认。

**会话查询是三态（第七版）**：读取函数返回
`Option<bool>`——`Some(false)` 已知普通会话 / `Some(true)` 已知禁用会话 /
`None` 未知或已驱逐。把 `None` 折叠成 `false` 会让每个调用方把未知
session id 当成宽松默认，而现有调用方恰恰都不能这样：扩展端点会用共享
registry 回答一个未知 id，握手会为一个根本没装上的会话给出确认。
**握手仅在 `== Some(true)` 时回显。**

**驻留 Load 的比较时序（第三版新增，T8/T9）**：对已有驻留 actor 的
`session_id`，比较必须发生在**任何 reconnect 副作用之前**——即在 MCP
重注册、client-hooks 装载、YOLO/权限模式重置等动作**之前**读
`SessionHandle` 的锁存值并判定；不一致立即返回
`{code:"local_extensions_disabled", policy:"local_extensions_disabled",
reason:"immutable_conflict"}`，**不执行任何副作用**。否则"先改状态再发现
冲突"会留下半改过的会话。

**WanCode 侧硬门**：`start_inner` 的 Chat 分支在拿到响应后立即校验——
字段缺失、为 `false`、或类型不符 ⇒ `cancel.cancel()`、**不安装 handle**、
返回结构化 `SURFACE_POLICY_BLOCKED{code: local_extensions_not_applied}`。
旧引擎（无此字段）因此**自动 fail-closed**，不会让 Chat 在"以为受保护"
的状态下运行。

## 5. 两个 list 的固定返回形状

禁用会话中恒为空，且**不是错误**（UI 可正常渲染空态）：

**必须沿用现有 DTO 的真实序列化**，不另造 wire 形状——
`HooksListResponse.load_errors` 带 `skip_serializing_if = "Vec::is_empty"`
（`xai-hooks-plugins-types/src/lib.rs:218`），空时**不出现在 wire 上**：

```json
// x.ai/plugins/list  →  PluginsListResponse { plugins: vec![] }
{"plugins": []}
// x.ai/hooks/list    →  HooksListResponse { hooks: vec![], project_trusted: false, load_errors: vec![] }
{"hooks": [], "projectTrusted": false}
```

实现要求：禁用分支**构造既有 DTO 再走同一 `to_ext_response`**，
不得手写 JSON 字面量——否则一旦上游给 DTO 加/改字段，禁用路径会与
正常路径产生形状分歧（第二版修订）。

理由：探针与 UI 都用"空数组"作为正证据；返回错误会迫使调用方区分
"禁用"与"故障"，反而更易 fail-open。

**未知 session id 一并 fail-closed（第七版）**：带 `sessionId` 的
list/action 遇未知 id——**list 返回空 DTO，action 返回结构化拒绝**，
一律**不得回落共享 registry**。此前 `plugins/list` 对未知 id 会用共享
snapshot 回答，等于让一个抢在会话拆除时刻、或干脆猜 id 的调用方拿到整机
插件清单。action 的未知 id 用**独立 reason**（`unknown_session`）与策略
拒绝区分，保持可诊断。

**注意实现顺序**：`plugins/list` 的策略判定必须在 `await`
**取到 handle 之后**——该 helper 会等待仍在加载的会话，先查表会把加载中的
普通会话判成未知并回空，那是对现有行为的改变，本批不允许。
**由 T24 锁定**：这个顺序在代码里只表现为两行的先后，极易在后续重构中被
"提前判定省一次 await"的直觉改回去，因此必须有可证伪契约而不是注释。

**整体零贡献要求（第五版口径）**：标志为 true 时，**所有外部扩展通道**
必须整体为零——见 §0 的语义表。注意范围**不限于"插件贡献的"**：
hooks 五源含 `AgentDefinition.hooks` 与 client hooks；MCP 四源含 managed
与请求/meta 通道；LSP 三源含用户与项目 `lsp.json`。任一遗漏都是注入口。
清空两个 list 只是**表象**，不是拦截手段。
Code 对照会话必须**全部仍可用**（T5 + T13d + T17 逐项相等）。

## 6. Code 默认路径逐项零变化

`local_extensions_disabled == false`（默认）时：

- `session_meta` 多认一个可选键；键缺失 = `false`，旧 meta 行为不变
  （第五版更正：**不是** `StartupHints` 加字段——那是连接级，见 §1.0）；
- 所有拦截点都是 `if local_extensions_disabled { … }` 的早退分支
  （策略位来自 actor/handle 的会话级字段），false 分支**逐字走原路径**；
- 两个响应多一个 meta 键（旧客户端忽略未知键）；
- **验收**：Code 会话的 `plugins/list`、`hooks/list`、命令列表、hook 派发、
  MCP 合并（四源）、LSP 启动（三源）与改动前逐项相等
  （T5 + T13d + T17 覆盖）。

## 6.1 测试架构裁决（第七版）

**不修上游基线错误**：`cargo check -p xai-grok-shell --lib --tests` 在
base commit `63d4eda` 上实测 **51 个错误**（独立 worktree 验证），根因是
结构性的——`MockEmbeddingProvider` 是**另一个 crate** 的 `#[cfg(test)]` 项，
跨 crate 原理上不可见；另有 `WorkspaceOps::for_test`(15)、
`MemoryStorage::with_paths`(6)、`crate::env::EnvVarGuard` 等。修它远超
白名单，**否决**。这也解释了为何 wancode CI 只跑单个 integration target。

**因此**：

| 项 | 内容 |
|---|---|
| feature | `local-extensions-test-support`（默认关闭，实测不改 `Cargo.lock`） |
| target | `crates/codegen/xai-grok-shell/tests/local_extensions_disabled.rs`（新增文件） |
| 运行方式 | 必须 `--test-threads=1`（`scratch_home()` 的单次环境写入以单线程为前提，`local_test!` 另有 runtime flavor 断言） |
| 命令 | `cargo test -p xai-grok-shell --features local-extensions-test-support --test local_extensions_disabled` |

**足场口径（第七版修订）**：分**两类**，均只在 feature 开启时编译，
默认构建里这些类型与等待点**根本不存在**；两类都**绝不参与策略判定**。

| 类 | 内容 | 为何必要 |
|---|---|---|
| **只读观察** | `ensure_plugin_registry` 调用计数；会话策略三态快照；**会话 actor 的原始 plugin registry（存在与否 / 插件数）**；父会话缺失时的继承判定 | 端点层对禁用会话恒返回空列表，纯 wire 断言即便 actor 已被污染也会绿——必须能问到端点**背后** |
| **确定性同步 / 故障注入** | `session/load` 的 barrier（登记为进行中、handle 尚未插入时暂停）；会话装配 failpoint；从会话表移除条目以便触发真实 Load | 竞态与装配失败窗口无法从外部编排；不能确定性进入的窗口，等于没有测试 |

**barrier 的硬性约束**：所有等待**必须有界**（当前 10s）。测试步骤写错
必须让它**失败**，而不是挂死——挂死的 CI job 最终会被静音而不是被修。

**优先级**：T1–T18 尽量全部走**公开 ACP wire**；T19/T20 优先用 mock 模型
驱动真实子代理链；**只有 wire 上无法观测的内部不变量**才用足场
（T21 的驱逐竞态即属此类——`ValidateType` 抢在父会话拆除时刻无法从外部编排）。

> 不把 `sessions` 等内部结构永久改成 `pub`：那是为测试付出的永久 API 代价，
> 而 feature 门控的只读函数可以随时删掉。

| T24a | **未知 ID fail-closed** | 四条同时成立：①仍在 Load 过程中的 **Code** 会话调用 `plugins/list`，必须**等待加载完成**后返回该会话的**真实 registry**；②**不得**被三态查询提前判为未知而回空；③真正未知的 session id 仍返回**空 DTO**；④禁用会话（无论是否加载中）恒空。锁住「先 `await` 取 handle、后判策略」的顺序——否则这处只有代码注释，没有可证伪契约 |
| T24b | **加载竞态：等待而非误判** | 用 barrier 确定性进入窗口：Load 已登记为进行中、handle 尚未插入 `sessions` 时发起 `plugins/list` ⇒ 必须**等待**并在 Load 落地后返回该会话的**真实 registry**（夹具 1 个插件）；同一窗口内对**真正未知的 id** 的查询必须**立即**返回空，不得被无关的 in-flight load 拖住 |
| T15 | **ACP MCP meta** | `_meta["x.ai/mcp/servers"]` 存在时禁用会话零 ACP MCP 注册；另加 WanCode 侧请求形状测试（Chat 构造器不产生该键） |

> T20 的前置条件是本条测试的**要害**：必须让共享 registry **先非空**
> （否则子代理拿到 `None` 可能只是因为全局没插件，测试是假绿）。

## 10. 构建清单更新：新增可执行的 `intentional-delta` 模式

**不能只是"跳过原 workflow"**（第二版修订）——那会让本批失去自动化
供应链验证。改为给 `scripts/migration_audit.ps1` 增加一个**并列模式**：

```powershell
scripts/migration_audit.ps1 -Mode intentional-delta `
  -BeforeSha <wancode-before> -Whitelist docs/design/v0.19-engine-file-whitelist.txt
```

**白名单必须机器可解析**（第五版收口）：**不读 Markdown 表格**——宽松
文本搜索会把说明文字里出现的路径误当白名单项，也无法检出重复/笔误。
改为独立的纯文本清单 `docs/design/v0.19-engine-file-whitelist.txt`：

```
# 一行一个仓库相对路径；# 开头为注释；空行忽略。
[product]        # 允许改动的既有产品文件（17 条）
crates/codegen/xai-grok-shell/src/session/handle.rs
…
[tests]          # 允许改动的既有测试文件（2 条）
crates/codegen/xai-grok-shell/src/agent/mvp_agent/tests.rs
…
```

脚本对该文件**严格解析**：非注释非空行必须落在某个段内、且是仓库内
**已存在**的相对路径；**段内重复、跨段重复、未知段名一律报错**；
差异集里出现清单外的**既有**文件报错；清单内文件**未被改动**只告警

## 11. 客户端 preflight 的降级（本次裁决的直接推论）

**问题**：现有 `enforce_chat_plugin_preflight` 会在"机器上存在供 Code
使用的插件"时阻塞 Chat 启动。接口落地后这是**过度阻塞**——生命周期
隔离已由引擎硬门负责，Chat 不该因为别的层要用插件而开不起来。

**调整**：

**只降级两项**（第二版修订：降级范围必须精确，不能顺手把无关硬门一起降）：

| 客户端门 | 处置 | 理由 |
|---|---|---|
| `enforce_chat_plugin_preflight`（插件来源扫描） | **降为诊断日志** | 生命周期隔离已由引擎硬门 ①②③ 负责；不该因机器上有供 Code 用的插件就拦住 Chat |
| `ensure_no_disk_global_hooks`（磁盘 hooks 扫描） | **降为诊断日志** | 由引擎硬门 ①⑥ 覆盖 |

**以下仍是独立硬门，一律保留阻断语义**：

- **managed MCP 实例级关闭**（`apply_chat_agent_config_overrides`）与
  **空 client MCP**（`NewSessionRequest.mcp_servers = []`）——第四版起
  **不再是唯一防线**：引擎侧已对四条 MCP 来源的**会话数据面连接**归零
  （定位表 §E；managed 配置的 agent 级控制面列举仍可能发生）。
  客户端两道保留为**请求构造证据 + 纵深防御**（也让请求形状测试有对象）；
- **Chat profile 工具裁剪**（`_meta.agentProfile` 的最小 tool_config +
  五关闭项 + hosted allowlist）——这是工具面的主防线，与本接口正交；
- **`ensure_chat_model_allowed`**（agent_type 冲突门）——防 profile 被
  strict harness 压过，引擎硬门不覆盖。

**marketplace 自动安装 / 远程 plugin settings：不保留客户端阻断**
（第三版裁决）。它们最终都只是**共享 plugin registry 的来源**；只要禁用
会话在初始构建、派生能力、broadcast、snapshot 四层都不消费该 registry，
就注入不到 Chat。

**承诺口径必须精确**：对外表述为「**Chat 会话不加载或执行本地扩展**」，
**不得**扩大为「共享引擎进程绝不安装插件或写插件存储」——同进程的 Code
会话仍可合法触发全局安装，那是它的正当能力。

**遗漏的独立客户端硬门（第三版新增）**：`_meta["x.ai/mcp/servers"]` 经
`parse_acp_mcp_servers(session_meta)` 注册 **ACP MCP**，它与
`NewSessionRequest.mcp_servers` 是**两条不同的路径**。Chat 会话构造器
必须保证该字段**缺失**，并加**请求形状测试**（断言构造出的
`NewSessionRequest._meta` 不含该键）。managed MCP 实例级覆盖继续保留。

> 净效果：Chat 的安全承诺从"启动前扫描 + 客户端裁剪"改为"引擎会话级
> 硬门 + 客户端工具裁剪"，前者的误伤消失，后者的强度提升。
