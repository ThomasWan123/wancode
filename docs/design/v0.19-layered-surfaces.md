# v0.19 设计稿：Work / Chat / Code / Cowork 四层界面（第二版）

> 状态：第二版待复核（第一版三项开放问题已裁决并落稿，G26 锁定项补齐）。
> 范围：**只定分层与验收线（G22–G26），不含实现**。
> 输入：feature-blueprint-2026H2 的 D8（Work 文档工作台）与 D4（后台派单）、
> Claude 的 Chat/Code/Cowork 三分层参照、#126 迁移后的 12 行 vendor 终态约束。

## 0. 一句话定位

分层是**导航与上下文预设层**，不是四个产品：同一引擎、同一会话存储、同一
权限体系，四层只在「预置工作区、可用工具面、默认权限模式、界面密度」上不同。
切层 = 换预设，绝不 fork 引擎行为——vendor wiring patch 保持 12 行终态，
分层零引擎侧改动（这是 G26 的硬线）。

## 1. 四层定义

| 层 | 一句话 | 工作区 | 工具面 | 默认权限 |
|---|---|---|---|---|
| **Chat** | 轻对话：问答/解释/起草，不访问用户/项目文件系统 | 无（会话落 ~/.grok；图片等输入落应用私有会话资产目录） | 仅联网 MCP（web-search/reader），文件/执行工具不注入 | manual（且无文件审批可弹） |
| **Code** | 现有完整编码工作台（默认层，今天的 WanCode） | 用户项目 | 全量 | 沿用用户设置 |
| **Work** | 开发者文档工作台（D8 一期 MVP：解析+来源引用） | `app_data_dir()/work/<workspace-id>/`（原件只读+记录哈希） | 读文档/检索/联网；**零代码执行** | manual |
| **Cowork** | 后台派单（D4 一期：单任务 worktree 编排） | 自动 worktree（隔离于宿主） | 全量（在 worktree 内） | 沿用 + 合并前人工验收 |

- 切换入口：左栏顶部四段选择器；当前层持久化 localStorage；会话归属层
  记录在会话 meta，恢复会话自动回到其层。
- Chat 层「零文件面」的准确定义（裁决①）：**不访问用户/项目文件系统**，
  而非进程绝对零写盘——会话记录、粘贴图片等输入落**应用私有会话资产目录**
  属正常运作。允许粘贴图片（多模态问答）。实现仍是客户端裁剪工具注入 +
  权限层双保险，不依赖模型自觉。
- Work 层暂存区（裁决②）：Tauri `app_data_dir()/work/<workspace-id>/`，
  不放项目内、不另造固定 `~/.wancode` 根目录。导入即记录原件 sha256，
  原件全程只读；任何导出都必须显式操作，无静默写出。
- Work 层安全底线（沿 D8 冻结结论）：文档内容永远是数据不是指令；永不
  覆盖原件；宏文件不执行。
- Work 层引用锚点（裁决③）：必须超过页码级——PDF 为
  `source_id + page + excerpt/chunk`，DOCX 为
  `source_id + paragraph/block anchor + excerpt`；引用可点击回到来源；
  找不到证据时明确回答「无法从文档定位」，禁止生成无锚引用。
- Cowork 一期只做「一句话任务 → worktree 子会话 → 完成报告 → 一键合并/
  丢弃」单任务闭环，不做队列/并行（那是 v0.21 的 D4 全量）。

## 2. 不做（本版）

多层并排视图、层间拖拽、Work 层生成/语义 Diff/连接器（D8 二期+）、
Cowork 多任务队列、通用办公助手定位。

## 3. 验收标准（G22–G26，入 golden-tasks 同格式）

| # | 任务 | 通过标准 | 方式 |
|---|---|---|---|
| G22 | 四层切换与归属 | 任意层间切换会话流不丢不混：各层各开一会话来回切，消息归属正确；重启后回到上次层，恢复会话自动回其归属层 | SEMI |
| G23 | Chat 层零文件面 | Chat 层跑「读 package.json / 写 test.txt」类 prompt：工具注入列表无文件/执行工具，会话记录零 tool_call 落盘文件写，test.txt 不存在；粘贴图片正常问答且图片字节只落应用私有会话资产目录（用户/项目目录零新文件） | AUTO（磁盘+updates.jsonl 断言） |
| G24 | Work 层文档理解 MVP | 拖入 PDF/DOCX 各一：问答引用带结构化锚点（PDF=source_id+page+excerpt/chunk；DOCX=source_id+paragraph/block anchor+excerpt），点击引用回到来源位置；无证据时回答「无法从文档定位」，零无锚引用；解析失败 fail-closed 明示；原件 sha256 前后一致 | SEMI + MANUAL（编造/无锚判定人工） |
| G25 | Cowork 单任务闭环 | 一句话任务派单：worktree 自动建、子会话完成出报告、合并后改动进宿主分支/丢弃后 worktree 清理，全程宿主仓库工作树零污染（porcelain 前后一致） | SEMI（git2 断言，串仓库 0 指标沿 G12） |
| G26 | 分层零引擎漂移 | 四项硬锁全部成立：①fork engine commit 不变（`63d4edab0…`）；②wiring patch 仍 12 行；③构建清单四项哈希（wiring/emergency/cargo_lock/effective_tree）逐一不变；④分层全部实现落在 WanCode 前端/Tauri 客户端层，`vendor/`、fork、引擎 crate 零改动（diff 路径断言）。另 smoke 6/6 在 Code 层全绿 | AUTO（verify + git diff 路径断言 + smoke） |

## 4. 依赖与风险

- Work 层文档解析选型（pdf/docx 的 Rust 侧库 vs 前端 wasm）是本版最大
  不确定点，设计评审后单独出选型短文；一期只承诺 PDF/DOCX 两格式。
- Cowork 依赖既有 worktree 快照/预检（G17 已验），派单壳新增面小。
- 蓝图原 v0.19 主打（D1 成本看板）顺延，不与分层抢同版。

   应用私有会话资产目录的写入属正常运作（→ §1 与 G23）。
2. Work 暂存区 = Tauri `app_data_dir()/work/<workspace-id>/`；原件只读 +
   记录哈希；导出必须显式操作（→ §1 与 G24）。
3. G24 引用锚点必须超过页码级：PDF=`source_id+page+excerpt/chunk`，
   DOCX=`source_id+paragraph/block anchor+excerpt`；可点击回源；
   无证据答「无法从文档定位」，禁止无锚引用（→ G24）。
