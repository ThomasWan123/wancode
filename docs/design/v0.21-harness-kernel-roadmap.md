# WanCode Harness Kernel 路线图（v0.21–v0.25）

状态：实施基线（2026-08-23）

产品基线：WanCode v0.20.3 / `d20a5dc1ed5c5d1a1fcf6cbc4c1b4d93f708dab4`

引擎基线：`ThomasWan123/grok-build@9e9adb62d3251c5cdafbbfe4dcc17ea83b411910`

## 0. 决策摘要

WanCode 不替换现有 grok-build 执行引擎，也不把 Codex 或 DeepSeek
Harness 整体嵌入产品。后续主线是在现有 Tauri/Rust + grok-build/ACP
之上增加一个由 WanCode 控制的 **Harness Kernel**：

1. 用 append-only Execution Ledger 记录可审计、可恢复的执行事实；
2. 用 Capability Lease 把 Surface、Agent、Workspace、Tool、MCP、Job 与
   文件根绑定为不可变授权；
3. 用单调拒绝的 Tool Policy Pipeline 保证后置插件不能扩大权限；
4. 用安全调度器并行只读调用、顺序提交写调用、完整收敛取消；
5. 用 Provider Profile 针对 GLM、DeepSeek 与自定义兼容端点选择提示、工具
   呈现、缓存与推理策略；
6. 只有上述边界经真实引擎和混沌矩阵证明后，才开放 Cowork。

这条路线保留 WanCode 当前最有价值的差异：供应商自由、分层 Surface、
Windows 原生进程治理、失败关闭、可验证更新链与文档 Work；同时吸收三个
上游已经证明有效的架构不变量。

## 2. 当前基线：保留、补强、暂不开放

### 2.1 已有且必须保留

- GLM、DeepSeek、自定义 OpenAI-compatible 的供应商身份链与能力快照；
- Chat / Code / Work 的不可变 Surface Binding 与 fail-closed 恢复；
- Code 的 MCP、Hooks、Skills、Plugins、Subagents、Terminal、Git、Worktree；
- Work 的 PDF/DOCX 只读暂存、哈希复核、受限 worker、可定位上下文；
- Windows Job Object 进程树治理、崩溃恢复；
- 固定引擎 commit、Cargo lock、有效树哈希和迁移审计；
- minisign 更新信任链、多镜像故障切换和发布证据纪律。

### 2.2 已有引擎能力，优先做审计同步/产品接线

- 跨会话 Memory 的搜索、刷新、编辑、阈值、注入来源和统计；
- 子代理角色/persona、模型选择和后台执行；
- MCP `all / none / named / except` 继承；
- Plugin/Hook 的项目信任与托管策略；
- 稳定提示前缀、压缩后重新注入和 Memory 遥测。

### 2.3 必须由 WanCode 自己掌握

- Surface 与供应商身份之上的授权内核；
- UI、ACP 和引擎之间的执行账本与恢复投影；
- 跨供应商统一的 Provider Profile 与合规证据；
- Windows 上进程、文件写、工作区和更新器的端到端治理；
- Work 文档来源真实性、引用和不可信内容边界。

### 2.4 暂不开放

- Cowork：Capability Lease、资源所有权和取消收敛完成前保持 gated；
- 默认 Code Mode：仅在每模型基准证明收益后按 Provider Profile 开启；
- 云端会话共享、自动合并、自动发布；
- macOS/Linux 桌面发行：不挤占 Windows 可信执行主线；
- 未经精确 commit 审计的上游整树同步。

## 3. 三个上游的可吸收能力

### 3.1 Codex：稳定桌面协议与权限可解释性

吸收：

- `thread -> turn -> item` 生命周期和 started/delta/completed 事件；
- thread resume/fork、turn steer/interrupt、分页历史；
- 每回合聚合 Diff、结构化 command/file-change 状态；
- 细粒度文件 read/write/deny、网络权限和审批策略；
- 命令分段后分别判定策略，复杂 shell 不冒充可静态证明安全；
- Windows 策略无法被选中后端等价执行时 fail-closed；
- 错误分类、耗时、退出码和审批结果作为 UI 一等数据。

WanCode 落点：统一前端事件模型、诊断时间线、权限说明卡和打包 GUI E2E。
不复制 Codex 的 OpenAI 专属认证、模型目录或云线程存储。

### 3.2 DeepSeek Harness：事件事实源与工具不变量

吸收：

- typed append-only SessionEvent；模型历史由事件投影，不另存第二份事实；
- 独立从日志重建冻结请求并比较，检测隐形上下文漂移；
- `pre-execute -> monotonic guard -> execute wrapper -> post-execute ->
  finalize -> observe` 工具管线；
- 模型可见工具 schema 采用 allowlist，host-only 字段永不外泄；
- 每 Agent 独立工具可见性和 shadow/restrict；
- native/code/both 工具呈现模式；
- concurrency-safe 工具进入有限滚动池，互斥工具形成屏障；
- 取消后未派发调用仍生成明确 call/result 终态；
- append-only prompt/schema/history 维持 KV cache 前缀稳定；
- DeepSeek cache-read token 和模型路由作为用量事实。

WanCode 落点：Execution Ledger、Capability Broker、Scheduler、Provider
Profile。DeepSeek Harness 仍是 Developer Preview，因此只移植经测试表达的
不变量，不把 Cordis/TypeScript runtime 纳入生产依赖。

### 3.3 grok-build：优先复用的成熟执行面

吸收/开放：

- ACP 会话、Terminal、Git、Worktree、MCP、Skills、Plugins、Hooks；
- 跨会话 Memory 与混合搜索；
- 子代理后台执行、角色与模型覆盖；
- MCP 细粒度继承；
- 沙箱、长任务、压缩、恢复等新上游修复。

WanCode 落点：继续固定在审计 fork。每次同步产出文件级变化清单、协议差异、
Cargo.lock 变化、许可证变化、Windows 行为回归和回滚点。上游声明其源码从
内部 monorepo 周期同步，不能假设历史总能 fast-forward；同步按“新基线内容
导入 + WanCode 提交重放 + 有效树验证”处理。

## 4. Harness Kernel 目标模型

```text
React/Tauri UI
  |
  +-- WanCode Thread / Turn / Item projection
  |
  +-- Execution Ledger (append-only, redacted, versioned)
  |      +-- recovery projector
  |      +-- diagnostic/export projector
  |      +-- request reconstruction invariant
  |
  +-- Capability Broker
  |      +-- immutable CapabilityLease
  |      +-- model schema allowlist
  |      +-- monotonic policy guards
  |      +-- approval receipts
  |
  +-- Scheduler
  |      +-- concurrency-safe rolling pool
  |      +-- exclusive mutation barriers
  |      +-- cancellation convergence
  |
  +-- grok-build ACP adapter
         +-- Provider Profiles (GLM/DeepSeek/custom)
         +-- Job/Terminal/MCP/Worktree resources
```

### 4.1 ExecutionEvent v1

所有事件共有：

- `schema_version`、`seq`、`event_id`、`time_unix_ms`；
- `session_id`、可选 `turn_id/step_id/call_id`；
- `surface_kind`、`policy_version`、`provider_catalog_key`；
- `kind` 与 kind-specific `data`；
- 敏感字段只能记录不可逆摘要或 `[REDACTED]`；
- 写入前完成大小限制和字段白名单，不记录原始凭据、完整环境或任意 shell
  secret。

首批事件：

1. `session.started / session.resumed / session.ended`；
2. `turn.started / turn.ended`；
3. `prompt.submitted`（正文仅哈希、长度和内容类型）；
4. `provider.requested / provider.completed / provider.failed`；
5. `tool.called / tool.completed / tool.denied / tool.aborted`；
6. `approval.requested / approval.resolved`；
7. `surface.bound / policy.applied / policy.rejected`；
8. `agent.spawned / agent.cancelled / agent.completed`；
9. `resource.created / resource.released`；
10. `checkpoint.created / recovery.completed`。

Ledger 是 WanCode 侧审计事实，不在 v0.21 一次替换 grok-build 的会话存储。
通过 adapter 投影 ACP 事件，先建立可迁移边界；等两个版本证据稳定后再评估
是否让 Ledger 成为完整模型历史的事实源。

### 4.2 CapabilityLease v1

Lease 至少绑定：

- session、surface、agent、parent-agent、workspace；
- provider route 和模型能力快照；
- 可见工具集合与每工具风险类别；
- readable/writable/denied roots；
- MCP server/tool 继承；
- terminal/job/worktree/resource 所有者；
- policy version、issued time、失效原因。

继承规则：子 Lease 只能是父 Lease 与目标 Surface policy 的交集；未知字段、
未知策略版本、缺 owner 或身份冲突全部拒绝。资源 ID 不是能力；只有持有匹配
Lease 的主体才能操作资源。

### 4.3 Tool Policy Pipeline

1. 解析并冻结模型参数；
2. schema allowlist 去除 host-only 字段；
3. 可扩展 pre-policy 决定 allow/deny/ask；
4. Surface/owner/root 等系统 guard 单调拒绝；
5. around wrapper 负责 timeout、metrics、有限重试；
6. tool body；
7. post-policy 负责结果裁剪和附加上下文；
8. definition finalizer 生成模型可见内容；
9. 冻结结果、写 Ledger、通知 UI。

任何后续步骤都不能把系统 guard 的 deny 改回 allow。

## 5. 实施版本与工作包

当前实施快照（2026-08-23）：L1–L7 已有后端可重演实现；C1/C2/C4/C5

列表过滤与销毁）；P1–P4 已有安全默认实现，并将有界只读
并发/写屏障接到引擎真实 `execute_tool_calls` 入口。L8、C3/C6、
Provider 实验开关、Cowork 与 OCR 仍保持 gated，不因路线图存在而视为
已交付。

## 6. 测试与证据矩阵

每个工作包必须同时覆盖：

1. 纯函数单测；
2. 多次写入再读最终状态的事务测试；
3. 负向测试旁的正对照；
4. RED-first 或 mutation 证明新增回归测试能失败；
5. ACP/真实引擎集成；
6. 打包 Windows GUI；
7. Win11 current、Win10 最终支持版本；
8. GLM、DeepSeek、custom mock 与预算化 live canary；
9. crash、kill、disk full、read-only、slow/partial provider、重复/乱序通知；
10. 100k 文件、10k changes、100 回合、低内存、多子进程；
11. keyboard/IME/200% zoom/screen-reader names/reduced motion；
12. B01–B10 三次竞争试验和原始证据归档。

证据状态只允许 PASS / FAIL / PARTIAL / NOT-RUN；NOT-RUN 必须给原因且不计分。

## 7. 指标和停止条件

| 指标 | 门槛 |
|---|---|
| 错误 provider/credential route | 0 |
| Surface/Agent/Workspace 越权 | 0 |
| 未配对 tool call/result | 0 |
| 凭据或 Authorization 泄漏 | 0 |
| 崩溃后孤儿 AI 子进程 | 0 |
| 打包 GUI flake | 30 轮后 <2% |
| Ledger 普通任务 p95 开销 | <=3% |
| 长会话内存 | 建立基线后不得无界增长 |
| 引用无法复算 | 0 |
| 发布时开放 P0/P1 | 0 |

任一安全边界无法在目标 Windows 环境可靠执行时，相关 Surface/功能保持 gated；
不得以文档警告代替技术边界。

## 8. PR 与发布切片

为控制评审大小，每个表格 ID 原则上一个 Draft PR；同一 schema + 最小实现可在
一个 PR，但禁止跨版本混合。推荐首批顺序：

1. `S0-1/L1`：文档、ExecutionEvent、Ledger store；
2. `L2`：Redactor；
3. `L3`：session lifecycle wiring；
4. `L4/L5`：turn/provider/tool projection；
5. `L6/L7`：recovery 与 reconstruction；
6. `L8`：UI；
7. v0.21 完整环境与混沌门；
8. v0.22 以后按依赖继续。

所有 PR 遵守 `docs/pr-review-protocol.md`：评审绑定精确 head；推送使旧 verdict
失效；合并和发布仍绑定用户批准的精确 SHA。开发授权不改变凭据、付费、外部
发布和不可逆操作的独立安全边界。
