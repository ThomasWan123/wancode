## 0. 一句话定位

Work = 文档工作台(解析 + 锚点级引用,零代码执行);Cowork = 单任务
worktree 派单闭环,**隔离档位由探针裁定,不由愿望裁定**。两层全部落在
客户端,G26 零引擎改动硬线不变。

## 1. Work 层工程决策(D8 一期 MVP)

### 1.1 解析选型(需 spike 实证后定稿)

| 格式 | 首选 | 理由 | 备选 |
|---|---|---|---|
| PDF | `pdfium-render`(Rust 绑定 PDFium) | 文本+页几何一次拿全,锚点可回源高亮;许可证宽松;纯本地 | `lopdf`(纯 Rust 但文本抽取弱) |
| DOCX | `docx-rs`(纯 Rust 读段落树) | 段落/块级锚点天然对应;零外部依赖 | mammoth 类转换器(丢结构,弃) |

**Spike 门槛(PR-W1,证据型 PR)——功能面 + 安全面双清单,全过才允许
PR-W3 动工**(codex R1-F3 修订):

功能面:三份真实样本(扫描件/中文/表格)——抽取率、锚点回源逐字一致、
扫描件按「无法定位」处理(不做 OCR,见 §4)。

安全面(解析的是**不受信输入**):
- 资源边界实测并定档:输入体积上限、解压后体积上限(DOCX ZIP 炸弹)、
  页/块数上限、单文档解析 CPU 时限与内存上限——超限一律 fail-closed;
- 对抗样本:截断 PDF、加密/不支持格式、DOCX 内路径穿越条目
  (`../` 解压逃逸)、XML 实体展开炸弹——全部拒收且零部分状态残留;
- **崩溃遏制**:解析跑在独立工作进程(超时可杀),Pdfium 原生崩溃/
  panic 不得带倒主应用;失败即整体拒收,暂存区无半成品;
- **Pdfium 供应链绑定**:二进制来源/版本/sha256/许可证入档,实测打包
  体积与目标架构对照打包门预算(§5 风险项就此闭合)。

### 1.2 锚点 wire 契约(G24 的机器可断言形态)

```json
{
  "anchor_schema": 1,
  "import_id": "ULID(导入时铸造,存暂存区清单,持久且不透明)",
  "source_sha256": "完整原件哈希(不截断)",
  "kind": "pdf | docx",
  "offset_unit": "utf16",
  "range_kind": "half_open_zero_based",
  "range_space": "raw",
  "locator": {
    "pdf":  { "page": 3, "chunk": 7, "raw_range": [120, 348] },
    "docx": { "block_path": "body/p[41]", "run_ordinals": [2, 3], "raw_range": [0, 96] }
  },
  "excerpt": "逐字摘录(展示用,归一形态),≤500 字符"
}
```

(codex R2-F4/F2 修订)契约要点:
- **身份**:`import_id` 为持久不透明 ULID + 全量 `source_sha256`,
  两者联合定位文档;重导入同一文件铸造新 import_id,旧锚仍指旧导入;
- **坐标系定死**(消除跨运行时歧义):偏移单位 = **UTF-16 code unit**
  (前端 JS 原生单位,查看器高亮无需换算);区间 = **半开、0 基**;
  区间寻址的是 `range_space:"raw"` 即**原始抽取文本**,不是归一文本——
  归一只用于 excerpt 相等性判定,不用于定位,因此不存在"归一改长度导致
  高亮错位";
- **canonical↔source 映射持久化**:解析期为每个 chunk 落一张
  raw-offset → 源几何(PDF: page + glyph bbox 序)/ 源节点(DOCX:
  run 序)的映射表存暂存区;点击引用经它回到精确位置;
- **定位子按 kind 必填**:PDF = page + chunk + raw_range(+ bbox 经映射);
  DOCX = block_path + run_ordinals + raw_range;同页重复 excerpt 由
  raw_range 唯一消歧;
- **归一化**:相等性判定 = NFC + 连续空白折叠为单空格,在此形态逐字符;
  定位不受归一影响(见坐标系条);
- **fail-closed**:source_sha256 失配 / locator 越界 / 映射缺失 →
  「来源已失效」,不近似指向;
- G24 电池新增**跨运行时定位用例**:CRLF、连续空白、组合字符、星平面
  字符(astral, UTF-16 代理对)、DOCX 拆分 run——断言的是**精确导航到
  目标 occurrence**,不止 excerpt 相等;外加同页重复消歧、重导入旧锚、
  删除/替换、错误哈希四类失配。

### 1.3 注入防线(G24 反向场景的实现位)

(codex R2-F1 修订)关键纠正:上一版把「中性回合零 tool call」当保证,
但那只观测模型在夹具里**恰好没调**——同一个模型同时看见不受信文档和
「用户请求」文本,注入文档仍可能发出 web/MCP 调用。保证必须是**非模型
的能力边界**:

- **默认能力面**:Work 会话默认**不注入联网/MCP 工具**(工具 schema 缺席);
  即便有旁路注入,gateway 也按会话能力位拒绝该类 tool call。文档/模型
  文本无法凭空「铸造」这个能力——这是策略层,不是 prompt;
- **单回合能力授予**:用户经**无歧义的 UI/命令入口**(按钮/斜杠命令,
  非自由文本)显式授予「本回合可联网」,授予令牌由前端铸造、随该回合
  下发,文档内容无从伪造;
- **断言**:无授予时断言工具 schema 缺席 **或** gateway 结构化拒绝
  (三类对抗夹具:文件写/web 外泄/MCP,中性回合下均被能力边界挡住);
  **正对照**:持有效授予时同一 web_search 正常执行;
- 数据信封 + 有限对抗语料保留为纵深,均不作为保证记账。

### 1.4 存储与身份

- 暂存区 `app_data_dir()/work/<workspace_id>/`(v0.19 裁决②原样)。
  (codex R2-F3 修订)**workspace_id 与 import_id 是两层身份,不得混用**:
  `workspace_id` = 持久 Work 工作区 ULID,一个工作区可含多篇文档;
  `import_id` = 每篇文档导入铸造(§1.2)。工作区清单
  `work/<workspace_id>/manifest.json` 维护 import_id → 原件哈希/暂存路径/
  映射表的映射,生命周期(建/导入/删/重导入)原子更新;
- **会话与检索绑定单一工作区清单**:一次 Work 会话/检索查询只读它所属
  `workspace_id` 的清单,文档不得跨工作区串;
- 与 Code 工作区无路径耦合;
- SurfaceKind 扩展 `work`:沿 §0.1 双层契约,G22⑤⑥ 的篡改/迁移反向
  场景对 work 同样适用,进 G22 断言矩阵新列;
- 原件导入即记 sha256、置只读属性;查看器与解析器只读打开;导出必须
  显式命令且落用户选择的目录(零静默写出,v0.19 底线原样)。

## 2. Cowork 层(D4 一期):探针先行

### 2.1 逃逸探针(PR-C1,证据型 PR,**实现前硬门槛**,v0.19 §1.1 原样)

真实引擎会话 + 真实 worktree,探针矩阵(codex R1-F2 修订):

- **正对照先行(同一夹具)**:确定性 worktree 内写入必须成功——证明
  引擎/工具执行路径是活的;死工具路径或模型拒绝不得被误判为拦截;
- 三项逃逸各自必须有**实际发出的 tool call 记录**:①绝对路径写宿主;
  ②`..` 相对路径逃逸;③symlink/junction 指向宿主后写入——每项的
  结构化拒绝记录须与该次操作精确对应(拒绝原因、目标路径);
- **哨兵文件**:探针前在宿主放置已知内容哨兵,探针后断言其字节/哈希
  与存在性均不变(抓改写与删除,不只抓新建);新建目标另有缺席断言;
- 拦截点必须在**策略层**,prompt 拒绝不算;
- 三项全拦 → 档 A 立项;任一失败 → **档 B**:每任务启动前显式确认框
  (同屏示 worktree 与宿主路径),未确认不启动(G25 反向断言原样)。
- 探针结论由 codex 复核 + 用户裁定档位后写入本稿修订版;**预期是档 B**
  (Windows 无进程级文件沙箱原语,v0.19 §1.2 已预判)——探针的价值是
  把预期变成证据,并留下档 A 的升级触发条件(未来若接入 C1 的 ETW
  审计/拦截能力,重跑探针可升档)。

### 2.2 单任务闭环(PR-C2,探针裁定后)

一句话任务 → 确认框(档 B)→ 自动 worktree + 子会话(后台会话通道,
复用既有 background_sessions 机制)→ 完成报告(diff 摘要 + porcelain
对账)→ 一键合并进宿主分支 / 丢弃并清理。不做队列、不做并行(v0.21)。

## 4. 不做(本版)

- OCR / 扫描件文本化(无文本层 → 「无法定位」);
- PDF/DOCX 以外格式(xlsx/pptx 等待需求信号);
- Cowork 队列/并行/跨任务依赖(v0.21 D4 全量);
- 文档编辑/批注回写(Work 是只读理解面);
- 档 A 沙箱自研(升档只经 C1-ETW 路线触发重探针)。

## 5. 风险

- pdfium 二进制分发体积(~5MB)与打包门资产上限——W1 spike 一并测量,
  超限则评估按需下载(需与更新链同级的完整性校验)或降级 lopdf;
- worktree 在用户仓库有未提交改动时的建立策略:一期只允许 clean 或
  显式 stash 后派单,拒绝在 dirty 树上静默操作(沿 vendor 审计教训);
- Work 大文档上下文预算:一期按检索式注入(命中 chunk 才进上下文),
  不整本灌入;检索实现允许朴素(BM25 级),语义检索不在本版。
