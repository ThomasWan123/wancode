# B1 基准协议 — 「比竞品好」的测量规程（v0.20，待 codex 评审）

> 来源：roadmap-v0.20 §2 B1 的 Step 1。**先有此规程（codex 评审通过），
> 后有任何跑分。** 本稿只定义测量，不报告任何结果。NOT-RUN / 无访问权
> 永远不得记为胜。

## 0. 目的与反作弊立场

「WanCode 比 Claude Code / Codex 好」在测量前只是口号。本协议的存在是为了
让结果**连我们自己想作弊都作不出来**：任务集冻结、配置披露、干预计数、
独立裁定、原始记录全留档。任何一项缺失，该轮结果作废（记 INVALID，
不进证据档，不对外引用）。

## 1. 任务集（冻结快照）

- 从 `docs/golden-tasks.md` 选 12 个任务，覆盖四类：bug 修复 / 特性实现 /
  重构 / 仓库理解问答。每类 3 个。
- 每个任务绑定：**冻结的仓库快照**（commit SHA + 完整归档哈希）、任务
  说明书（逐字）、验收检查表（可机判的断言 + 需人判的语义项，分开标注）。
- 快照与说明书入 `docs/evidence/b1/tasks/`；一经入档即冻结——修订只能
  新增任务版本号，不得原地改（否则历史轮次不可比）。

## 2. 被测方配置披露（每轮必填）

| 字段 | 说明 |
|---|---|
| 产品 + 版本 | 含构建号；WanCode 侧记 commit SHA |
| 模型 + 端点 | 三方尽量同模型；无法同模型时**如实记录差异**，不得宣称等价 |
| 权限/工具面 | 三者都开「等效全自动」：WanCode = auto 模式；竞品 = 其对应的
  自动批准档。差异必须记录 |
| 环境 | 同一台机器、同一网络窗口期；系统提示/钩子全部默认 |

无法读取的 token/内部计量字段记 `UNAVAILABLE` 并说明原因；它不会伪造为 0，
也不会单独使整轮作废。只有使用该字段的比较维度不能下结论。

## 3. 执行规程

- 每任务每产品 **3 次独立试验**（新会话、清缓存态）。报告均值 + 最差值；
  只报均值是作弊（藏方差）。
- 产品执行顺序按预先生成的随机种子做平衡轮转，并记录种子；不得总让某一
  产品吃到更热的缓存或更好的网络时段。任务内的三次试验分散到轮转中。
- **干预计数**：任何人工提示/纠正/重试都记数并分类（澄清需求 / 纠正方向 /
  恢复死机）。「零干预完成」与「干预后完成」分开记分——后者不得充当前者。
- 原始记录全留：完整 transcript、工具调用流、token 与耗时、最终 diff，
  落 `docs/evidence/b1/runs/<date>/<task>/<product>/<trial>/`。
- 入档前运行固定脱敏器并人工复核：密钥、令牌、账号标识、绝对用户路径和
  私有仓库内容不得进入公开仓库。原始未脱敏记录只放访问受控的临时证据区，
  设定删除期限；公开 transcript 必须保留脱敏报告及内容哈希。
- 成本归一：按 token 单价折算每任务美元成本（披露单价来源日期）。

## 4. 裁定（独立于被测方）

- 机判项：验收断言脚本全绿 = pass，否则 fail。脚本随任务冻结。
- 语义项：由**不参与该轮执行**的评审按检查表盲判（不知道哪个 diff 来自
  哪个产品——顺序打乱、标识剥离）。
- 争议仲裁：执行人与盲判人分歧 → 第三人（用户）裁定，记录理由。
- **NOT-RUN 纪律**：某产品在某任务无法运行（无账号/不支持该平台/崩溃）
  → 记 NOT-RUN 并附原因，**不得记胜也不得记负**；该任务从可比集合剔除
  并披露。所有产品均完成的任务才进入三方配对比较；同时公布每个产品的
  完成覆盖率。若任一产品配对覆盖少于预注册任务的 80%，不得发布“领先”
  或“更好”的总括结论，只能发布探索性结果。

## 5. 记分与发布

- 每任务维度分：完成度（机判）、语义质量（盲判）、干预次数、wall time、
  成本。不设单一「总分」——总分权重本身就是作弊面。
- 结果页：有利与不利结果**同等发布**（docs/evidence/b1/），README 链接
  的是「方法 + 全部结果」页，不是精选截图。
- 在开跑前冻结分析计划：每个维度的统计量、并列规则、缺失数据处理、
  80% 覆盖门和允许使用的结论措辞。跑完后新增分析只能标为探索性，不能
  回写成预注册结论。
- 每个 release 重复一轮；任务集版本升级须说明并保留旧版结果可查。

## 6. 明确不做

- 不跑 SWE-bench 等公开基准充数（污染与过拟合已知；我们的任务是
  用户真实工作流）。
- 不用「内部评测链接」替代原始记录——没有 transcript 的结果不存在。
- 不在竞品无账号时发布「对比」——那是缺数据，不是领先。
