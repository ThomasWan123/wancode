# 注入面定位表（`local_extensions_disabled` 开工前置）

> 状态：**第二版（三项裁决落实），fork 未动**。语义已收敛为：
> **禁用会话只能使用内建工具，所有外部扩展通道归零**。
> 每条给出：来源 → 转换 → 会话落点 → 热更新入口 → 主拦截点 + fail-safe →
> Code=false 保持不变的机制 → 判别测试形状。
>
> 引擎路径均相对 `crates/codegen/xai-grok-shell/src/`（另注明者除外）。

## 0. 首要结论：两个 registry 字段，拦截必须落在**会话本地**那一个

定位中最重要的发现——插件 registry 在引擎里有**两份**：

| 字段 | 位置 | 语义 |
|---|---|---|
| `MvpAgent.plugin_registry_handle` | `agent/mvp_agent/mod.rs:833` | **共享**（`SharedPluginRegistryHandle`），进程级，broadcast 的源 |
| `SessionActor.plugin_registry` | `session/acp_session.rs:934` | **会话本地** `RefCell<Option<…>>`，会话真正消费的那份 |

`SessionActor` 另存 `plugin_registry_handle: Option<…>`（`acp_session.rs:938`）。

**因此拦截的主战场是"会话本地字段永远为 `None`"**，而不是去改共享 registry
——后者是 Code 的正当能力（§1.3 承诺口径：不承诺"进程绝不安装插件"）。
一旦 `SessionActor.plugin_registry` 恒 `None`，下游多条链会**自然归零**
（skills、commands gate、slash 展示），这也解释了为什么零贡献能做到而不必
逐个下游打补丁。

## 0.1 入口最早解析（第二版 P0 时序裁决）

**实测顺序问题**：`resolve_mcp_servers` 发生在 actor 构建**之前**，且它内部
调 `ensure_plugin_registry`（`agent_ops.rs:334`）：

| 入口 | `resolve_mcp_servers` 调用点 | 驻留检查位置 |
|---|---|---|
| `new_session`（`acp_agent.rs:811`） | **:835** | — |
| `load_session`（`acp_agent.rs:1256`） | **:1295** | `sessions.borrow().get(&session_id)` 在 **:1295 之后** |

后果两条：

1. 禁用会话会**先解析并合并 MCP、还顺带初始化了共享 plugin registry**，
   等走到 `agent_ops` 才发现策略——副作用已经发生；
2. 驻留 Load 的冲突比较若排在 :1295 之后，**"零副作用冲突拒绝"不成立**
   （MCP 已重解析）。

**裁决**：策略位在 New/Load 入口**最早**解析——`new_session` 在 :835 之前、
`load_session` 在 :1295 之前，紧跟 `arguments` 可用之后：

```
new_session:  parse(arguments.meta) → [禁用? MCP 归零，跳过 resolve] → …
load_session: parse(arguments.meta) → 驻留冲突比较（早退）→ [禁用? 同上] → …
```

`load_session` 的驻留冲突比较必须**上移到 :1295 之前**，与 D5
`reconnect_client_hooks`（:1709）的先后关系自然满足。

## A. LSP（第二版裁决：**Chat 全面禁用**，不只 plugin 贡献）

| 项 | 内容 |
|---|---|
| 来源 | ①插件 manifest `lsp_config_path` / `inline_lsp_servers`（`plugins/manifest.rs:169`）；②用户 `~/.grok/lsp.json`；③项目 `.grok/lsp.json` |
| 转换 | `agent_ops.rs:3267` 取共享 snapshot → `lsp::config::load_servers_with_plugins_sourced(cwd, plugin_paths, inline, …)`（**同一函数同时加载用户/项目 lsp.json 与插件贡献**）→ `folder_trust::filter_untrusted_project_lsp` |
| 会话落点 | `tool_ctx.lsp_server_names` + **`LspManager` 后台进程**（`agent_ops.rs:3300+`） |
| 初始入口 | 会话构建期 `if lsp_tools_enabled && tool_ctx.lsp.is_none()`（`agent_ops.rs:3265`） |
| 热更新入口 | 无独立 reload；新会话（含 Load 重建）重走该块 |
| 主拦截点 | `agent_ops.rs:3265` 条件加 `&& !local_extensions_disabled` ⇒ **整块跳过**：三个来源一并归零，`lsp_server_names` 为空，**`LspManager` 从不构造** |
| fail-safe | `LspManager` 构造点再加一次断言式早退（防将来有人拆分该条件块） |
| Code=false | 条件为 false 时逐字走原路，三个来源照常加载 |
| 判别测试 | **T13a** plugin manifest LSP；**T13b** `~/.grok/lsp.json`；**T13c** 项目 `.grok/lsp.json`——三者在禁用会话中均**无 LSP 名称、无子进程**；Code 对照三者均正常启动 |

> **裁决依据**：LSP 会启动本地后台进程并读取工作区，与 Chat 的零文件面
> 直接冲突；**是否经插件贡献不改变风险**。拦截必须在 `LspManager` 构造
> **之前**——事后 kill 不算隔离。
>
> 语义影响：本条使接口从"禁本地扩展"扩大为**"禁用会话只能用内建工具"**，
> 已在 §0 与接口草案 §1 同步登记。

## E. MCP 全来源（**四条，引擎侧全部归零**）

> **第二版裁决**：删除"managed MCP 不属于本接口"的表述。理由——Chat/Code
> **共用连接**，而客户端的 managed-MCP 实例级覆盖是**连接/进程级**手段，
> 不构成会话级边界。禁用会话必须在**引擎内**同时归零四条来源。
> 客户端现有四道检查**继续保留**，作为请求构造证据与纵深防御，
> **但不再是唯一防线**。Code 会话照常使用 MCP。

| # | 来源 | 落点/入口 | 引擎侧拦截点 |
|---|---|---|---|
| E1 | **plugin MCP** | `agent_ops.rs:337 merge_managed_mcp_servers(..., plugin_registry_handle.snapshot(), ...)`；reload 时 `hooks_plugins.rs:902` 重新合并并建连 | 禁用时不进入 merge（§0.1 早退，整个 `resolve_mcp_servers` 跳过）；reload 路径由 `apply_..._snapshot` 早退挡住 |
| E2 | **managed MCP** | `agent_ops.rs:335 get_managed_mcp_configs()`；开关 `acp_agent.rs:373` | 禁用时**不调用** `get_managed_mcp_configs`（随 §0.1 整块跳过），与 `cfg.managed_mcps_enabled` 无关 |
| E3 | **请求 `mcp_servers`** | `new_session acp_agent.rs:833/835`、`load_session :1295` | 禁用时**丢弃** `arguments.mcp_servers`，不传入 resolve |
| E4 | **`_meta["x.ai/mcp/servers"]`** | `agent_ops.rs:3523 parse_acp_mcp_servers(...)` | 禁用时**忽略该字段**（meta 通道，第三方客户端也可能带） |

**统一实现形态**：§0.1 的入口早解析后，禁用分支直接以
`(mcp_servers = [], managed_mcp_expires_at = None)` 替代整个
`resolve_mcp_servers` 调用——四条来源一并归零，且**不触发**
`ensure_plugin_registry`。E4 另在 `agent_ops.rs:3523` 单独早退。

Code=false：四条全部走原路。

## F. 驻留 actor：策略位的读取位置与同步判定

**问题**：`extensions/*` 与 broadcast 需要在**不向 actor 发消息**的情况下
同步判定策略位（发消息是异步的，且 broadcast 遍历时不能逐个 await）。

**定位**：`SessionHandle`（`session/handle.rs:41`）是 `MvpAgent` 侧持有的
会话句柄，`session_handle_waiting_for_load`（`agent_ops.rs:1742`）是统一
取用入口，`extensions/plugins.rs:142`、`acp_agent.rs:2187/3277/3322` 都经它。

**方案**：在 `SessionHandle` 上加 `pub local_extensions_disabled: bool`
（**普通 bool，非锁**——构造时写入、之后只读，避免 broadcast 遍历时取锁）。

| 消费方 | 读取方式 |
|---|---|
| `extensions/plugins.rs` / `hooks.rs` / `session_admin.rs` | `session_handle_waiting_for_load(&sid)` → 读字段 → 拒绝或返回空 DTO |
| `broadcast_plugin_registry_to_sessions`（`mvp_agent/mod.rs`） | 遍历 `self.sessions` 时读字段 → 跳过 |
| Load 冲突比较（T8/T9） | `acp_agent.rs` Load 分支**最先**读该字段与请求值比较，**早于** D5 的 `reconnect_client_hooks`（:1709）与其他 reconnect 副作用 |
| 握手 `applied`（T12） | 新建取新 actor 构造结果；Load 取 handle 字段 |

`SessionActor` 侧同名字段（`acp_session.rs`）供 actor 内部逻辑（skills
reload 早退、hook dispatch 早退）使用。**两处必须在同一构造点写入同一值**，
测试断言二者一致（防"handle 说禁用、actor 没禁用"的分裂）。

## H. 三项裁决（已定，第二版落实）

| # | 议题 | 裁决 | 落点 |
|---|---|---|---|
| 1 | `AgentDefinition.hooks` | **忽略 + 诊断日志**，不拒绝建会话；不改共享 profile 对象 | §D 的 D3 行 |
| 2 | E2/E3 引擎侧兜底 | **必须兜底**——Chat/Code 共用连接，客户端实例级覆盖不是会话级边界；四源引擎内全归零，客户端四道检查保留为纵深防御 | §E 全节 |

**语义收敛结论**：`local_extensions_disabled` 现覆盖 **plugins、所有 hooks、
所有非内建 MCP、所有 LSP、plugin skills/commands**——即
**禁用会话只能使用内建工具，所有外部扩展通道归零**。
