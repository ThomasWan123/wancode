# A3 — 更新链多镜像容灾（v0.20）

> 来源：roadmap-v0.20 §1 A3。现状：gh-proxy 单点 + 一次已记录的零字节事故；
> 重试 ≠ 容灾。实现已进入 v0.20 集成分支：客户端逐源编排、最高版本不降级、
> 双 manifest 发布合同均有自动门禁；真实签名资产的双源下载仍在发布后 E2E
> 清单中，未跑前保持 **NOT-RUN**，不冒充上线证据。

## 0. 威胁模型与第一原则

**镜像只是运输层，永远不是信任根。** 信任链只有一个根：`tauri.conf.json`
里钉死的 minisign 公钥。Tauri v2 的 `latest.json` 本身不是签名对象；其中
`platforms.*.signature` 验证的是安装包字节。因此 manifest、版本号和 URL
都按**不可信元数据**处理，只有下载后的安装包通过同一把公钥验签，才允许
进入安装路径。镜像作恶/被劫持的最坏结果可以是更新不可用（拒绝服务），
但永远不得变成「执行了错字节」。

## 1. 现状（故障面盘点）

- manifest：`endpoints = [GitHub origin latest.json]`（单点）。
- 字节：release.ps1 把下载 URL 写成 gh-proxy 前缀（单点；零字节事故即此）。
- 插件行为：`check()` 按序试 endpoints，第一个**可解析且版本适用的 manifest** 胜出；
  `download()` 只认胜出 manifest 里的 URL，失败即报错——**没有字节级容灾**。

## 2. 设计：每镜像一份 manifest（N 源 × N manifest，安装包统一签名）

不为字节重写 URL（那会绕开插件的内建验签）。改为**每个源一份 manifest**：

- release.ps1 生成 `latest.json`（origin 形态）+ 每个镜像各一份
  `latest-<mirror>.json`——内容仅 `platforms.*.url` 的主机前缀不同，
  **同一版本号、同一安装包 minisign 签名**（签的是字节，与来源无关）。
  全部随 release 资产发布（origin 资产 + 镜像路径规则）。
- 客户端保留内置有序 endpoint 表，但不把插件“一次 `check()` + 一次
  `download()`”当成容灾循环。新增 updater orchestration 层：逐源独立
  `check()`，收集候选，再逐候选 `download()`；每一步都有有界超时。
- 检查更新：收集所有**可解析且版本适用**的 manifest。同一轮取版本号最高
  的候选组；同版本内 origin 优先、镜像按内置顺序。manifest 无法证明自身
  真实性，版本比较只用于可用性/防陈旧，不能算安全校验；恶意高版本造成的
  拒绝服务属于威胁模型明确接受的剩余风险，并必须上屏留痕。
- 下载：用候选 manifest 的 URL 走插件 `download()`（安装包验签在插件内）。
  **字节失败（零字节/截断/校验不符/超时）→ 不执行、不部分落盘，
  滑向同版本下一源的 manifest 重试下载**；不得因高版本组失败而静默安装
  更低版本。全部源失败 → 报错并把逐源失败
  原因上屏（UI 可见，不静默）。
- 安装前复核（既有不变）：落盘文件 sha256 与验签通过字节一致才允许
  `spawn_breakaway_verified`。

## 3. 失败分类账（每源一条记录，随错误上屏）

| 类别 | 检测点 | 行为 |
|---|---|---|
| manifest 不可达/超时 | check | 下一源 |
| manifest 不可解析/字段非法 | schema/URL/version 校验 | 下一源（记 warn；不得称为签名失败） |
| manifest 版本低于已见最高 | 版本比较 | 跳过该源（防降级） |
| 字节零字节/截断 | 下载长度/读回校验 | 下一源重下 |
| 字节与签名不符 | 插件验签 | 下一源（安全事件） |
| 全部源失败 | — | 结构化错误上屏，不执行任何字节 |
| origin 恢复 | 下一轮 check | origin 优先序自然回归 |

## 4. 配置形态

`tauri.conf.json` 的 `endpoints` 为静态编译期值；镜像清单演化为
**内置有序表 + release 资产命名约定**（`latest.json` = origin 形态，
`latest-<mirror>.json` 每镜像一份）。不把镜像列表放进运行时配置——
运行时改列表 = 运行时可引导到恶意源，削弱固定攻击面的纵深。即使固定列表
中的主机被劫持，安装包验签仍是最终执行门。新增/下线镜像 = 发版级变更。

## 5. 验收（E2E，全部自动化）

`scripts/verify-update-e2e.ps1` 扩展为多源版（本地 HTTP 夹具模拟各源）：

1. 正对照 A：仅 origin 健康 → 从 origin 完成更新。
2. 正对照 B：origin 挂、镜像健康 → 从镜像完成更新（字节与 origin 逐字节同）。
3. 零字节：镜像返回 0 字节 → 滑源，不执行。
4. 截断：字节截半 → 验签失败 → 滑源。
5. 篡改：字节可下载但与 manifest 中的安装包签名不匹配 → 滑源且**该源本轮不再被重试**。
6. 陈旧 manifest：镜像报旧版本 → 选最高版本源。
7. 超时：源 hang → 有界超时后滑源。
8. origin 回退：全镜像挂、origin 活 → origin 完成（fallback 方向正确）。
9. 全灭：所有源失败 → 结构化错误，应用内可见，无部分状态。
10. 伪造 manifest：镜像声明虚假高版本/任意 URL → 最多造成显式 DoS，
    未通过固定公钥验签的安装包绝不进入安装/执行路径。
11. 降级方向：最高版本候选下载失败时不得静默安装更低版本。

每项夹具同时断言：实际请求顺序、逐源失败分类账、临时文件清理，以及
`spawn_breakaway_verified` 的调用次数（失败路径必须为 0，正对照必须为 1）。

当前自动证据：

- Rust 单测锁定最高版本组、同版本源顺序与禁止降级；
- `scripts/test-update-manifests.ps1` 锁定两份 manifest 同版本、同签名、
  origin/镜像 URL 形态与无 BOM；CI 每轮执行；
- `scripts/verify-update-e2e.ps1` 的真实安装/重启链在 v0.20.0 资产发布后执行，
  结果补入发布证据；发布前不把它标为 PASS。

## 6. 明确不做

- 不做 P2P / CDN 自动发现（列表必须编译期固定）。
- 不在运行时接受用户自定义镜像（引导恶意源的面）。
- 不改变 minisign 密钥形态与发布签名流程（A1 的 Authenticode 是独立轨，
  仍按用户 2026-08-11 裁定 deferred）。
